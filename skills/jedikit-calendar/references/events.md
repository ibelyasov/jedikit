# События

Событие — обязательство со временем: встреча, приём, договорённость. В календарь попадает то, что занимает определённый промежуток в определённый момент и должно быть видно на ленте дня. Правила разрешения и отчёта — [operation-policy.md](operation-policy.md); поля — [calendar-tools.md](calendar-tools.md).

## Создать

1. Используй известные данные. Обязательны название, дата, время начала либо явное «весь день», длительность либо окончание. Для одного явно указанного all-day дня конец — следующая дата; дополнительных вопросов о часах не нужно. Все остальные блокирующие пробелы спроси одним сообщением. Место и описание добавляй только если названы; не придумывай их.
2. Установи домашний пояс из [настроек](setup.md), получи текущую дату через `get-current-time`. Другой пояс применяй только если пользователь назвал его для конкретного События. Относительный день недели — ближайший будущий: если сегодня четверг, «в четверг» означает через неделю; «сегодня» означает текущую дату. Покажи получившуюся дату в результате, не переспрашивай её.
3. Проверь календарь записи и однозначность аккаунта. Повтор передай массивом `recurrence` по названным дням/частоте/окончанию; не придумывай срок серии. Договорённое занятие привычки, например плавание с тренером, — Событие; сама привычка и её Отметки остаются в Habitify.
4. Прочитай затронутый диапазон календарей чтения, покажи пересечения. Передай `calendarsToCheck` и `sendUpdates: "none"`, без участников. Конфликт не разрешает переносить или сокращать другие записи; выполни только команду пользователя и отчитайся о фактическом ответе. После отказа из-за дубля покажи найденное Событие; обход защиты — только после «создай всё равно», по техническому контракту.
5. Выполни создание по правилам разрешения, затем `get-event` и сопоставь поля. Верни название, дату, начало–окончание, пояс, календарь и полученную ссылку. Неподтверждённый результат обозначь `unverified`, повторной записи не делай.

Время неизвестно или договорённости нет → «Это задача, а не Событие: „…“. Завести?» По «да» загрузи `jedikit-tasks` и его правила записи; встреча без даты тоже передаётся как задача. Не выдавай передачу за выполненную, если хост не загрузил скилл. Если намерение требует глубокого уточнения, используй `grill-me`, а при его отсутствии рекомендуй установить средствами хоста, без собственного интервью.

Точное расписание досуга самостоятельно не предлагай. Договорённость с людьми — Событие, явную просьбу поставить отдых выполни. Исследование [Tonietto и Malkoc](https://doi.org/10.1509/jmr.14.0591) обнаружило снижение удовольствия при точном планировании некоторых занятий; это ограниченный результат, а не запрет календарного досуга или универсальная норма отдыха.

## Найти, перенести, изменить

Прочитай названный диапазон в календарях чтения, запроси описание и поля серии. Несколько кандидатов покажи с названием, датой, временем и календарём; все блокирующие пробелы, включая режим серии, собери в одном сообщении. Не выбирай только по одинаковому названию. Запись разрешена лишь в календаре записи.

Для однозначной полной команды действуй сразу + Read-back. Перед update перечитай выбранный объект. При переносе с сохранением длительности вычисли новый конец по прочитанному интервалу; если длительность неизвестна, спроси. Сохраняй незатронутое описание, метки и повтор. Для смены времени передай пояс, `checkConflicts: true`, `calendarsToCheck`; во всех записях `sendUpdates: "none"`.

Для повторяющегося События уточни режим, если он не назван: только это вхождение, это и следующие, вся серия. Не спрашивай повторно уже выбранный режим.

| Режим изменения | Вызов |
| --- | --- |
| Только вхождение | `update-event`, ID подтверждённой серии, `modificationScope: "thisEventOnly"`, исходный `originalStartTime` |
| Это и следующие | `update-event`, ID серии, `modificationScope: "thisAndFollowing"`, `futureStartDate` выбранного вхождения |
| Вся серия | `update-event`, ID серии, `modificationScope: "all"` |

`originalStartTime` — исходное время вхождения даже после переноса; [Google различает его и фактический start](https://developers.google.com/workspace/calendar/api/guides/recurringevents). Используй реально полученные ID и поля. Если идентичность/исходное время не установлены, останови зависимое изменение; не вычисляй ID экземпляра. После разделения серии проверь обе части по правилам Read-back.

## Удалить или отменить

Полную однозначную команду выполняй сразу, без отдельного подтверждения, после проверки `organizer` по operation-policy.md. Приглашённое Событие с явно другим организатором не удаляй: это может означать RSVP-отказ, который вне сценария. Несколько кандидатов и невыбранный режим серии требуют уточнения, не дополнительного ритуала согласия.

| Что удалить | Действие |
| --- | --- |
| Одиночное Событие | `delete-event` с полученным ID |
| Одно вхождение | `delete-event` только с реально полученным и проверенным ID экземпляра |
| Вся серия | `delete-event` с подтверждённым ID серии |
| Это и следующие вхождения | `update-event` серии, `modificationScope: "all"`, окончание `RRULE` через `UNTIL` до выбранного вхождения; это ограничение серии, не delete |

У `delete-event` нет `modificationScope` и полей выбора даты: не передавай их. Вживую не проверено, возвращает ли `list-events` ID экземпляров и `recurringEventId`. Если ID экземпляра нет, прямо скажи, что удалить одно вхождение этим контрактом нельзя. Предложи изменение вхождения через `update-event`, если есть ID серии и `originalStartTime`, либо удаление всей серии по явному выбору; изменение не называй удалением. Поля `status` для отмены в update нет, не изобретай его.

Для «это и следующие» перечитай полное правило серии и исходную границу выбранного вхождения. Задай включительную границу `UNTIL` строго раньше него, с корректным типом даты/времени и UTC для timed повтора с поясом; не совмещай `COUNT` и `UNTIL`. Сохрани остальные условия повторения и прошлые вхождения. Если RDATE, исключения, перенесённые вхождения или неоднозначная граница не позволяют безопасно ограничить серию этим правилом, остановись и назови ограничение; не заменяй операцию массовым удалением. Если выбрано самое первое вхождение, весь остаток совпадает со всей серией: объясни это последствие до выбора действия.

После записи — Read-back. При delete сообщи название, дату/время, пояс, календарь и срок корзины: по [справке Google](https://support.google.com/calendar/answer/37113?hl=en), удалённое Событие хранится 30 дней, восстановление — в интерфейсе Google. Для «это и следующие» через ограничение правила отдельно скажи, что удалённого События в корзине нет и восстановление оттуда не обещается. Google также исключает режим «это и следующие» из восстановления через корзину.

## Встреча из Inbox

При явной передаче от `jedikit-tasks` используй уже названные поля и собери остальные одним сообщением. Создай Событие и выполни Read-back. Верни скиллу-владельцу результат `applied` с фактическим ID, календарём, датой, временем и ссылкой, чтобы он отменил исходный Inbox item по своим правилам. Сам Inbox не меняй. При ошибке или `unverified` сообщи, что создание не подтверждено и исходный Inbox item должен остаться; не повторяй create вслепую.
