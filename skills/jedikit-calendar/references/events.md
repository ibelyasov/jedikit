# События

Событие — обязательство со временем: встреча, приём, договорённость. Разрешения, Read-back и отчёт — [write-policy.md](write-policy.md); аргументы — [tools.md](tools.md).

## Создать

1. Обязательны название, дата, начало или явное «весь день», длительность или конец. Для одного all-day дня конец — следующая дата, о часах не спрашивай. Место и описание добавляй, только если названы.
2. Пояс — домашний; другой — только если пользователь назвал его для этого События. Относительный день недели — ближайший будущий: если сегодня четверг, «в четверг» — через неделю, а сегодняшний день называют «сегодня».
3. Календарь записи и аккаунт должны быть однозначны. Повтор задай через `recurrence` по названным дням, частоте и окончанию. Напоминания — по настройке Событий (к all-day она не применяется) или явному указанию в запросе ([tools.md](tools.md#напоминания)).
4. Прочитай затронутый диапазон календарей чтения и найди пересечения: набор агента показывает их в Preview, полная явная команда выполняется, а пересечения и `conflicts` попадают в отчёт. Передай `calendarsToCheck`; конфликт и отказ из-за дубля обрабатывай по [tools.md](tools.md#конфликты-и-дубли).
5. Создай; Read-back и отчёт — по [write-policy.md](write-policy.md#выполнение-и-read-back).

Договорённое занятие привычки, например плавание с тренером, — Событие; сама привычка и её Отметки остаются в Habitify.

## Не Событие

Время неизвестно или договорённости нет: «Это задача, а не Событие: „…“. Завести?» По «Да» передай `jedikit-tasks`. Встреча без даты — тоже задача.

## Досуг

Точное расписание отдыха сам не предлагай: в исследовании [Tonietto и Malkoc](https://doi.org/10.1509/jmr.14.0591) точное планирование некоторых занятий снижало удовольствие. Это ограниченный результат, а не запрет: договорённость с людьми — Событие, явную просьбу поставить отдых выполни.

## Найти, перенести, изменить

1. Прочитай названный диапазон в календарях чтения. Несколько кандидатов покажи с названием, датой, временем и календарём; по одному названию не выбирай.
2. Для повторяющегося События, если режим не назван, спроси: только это вхождение, это и следующие или вся серия. Вопрос о режиме и о кандидате задай одним `clarify`; выбранный режим не переспрашивай. Аргументы режима — [tools.md](tools.md#повтор-и-режимы-серии). Если ID серии или исходное время вхождения не установлены, зависимое изменение не выполняй.
3. Перед update перечитай объект. При переносе сохрани длительность: новый конец вычисли по прочитанному интервалу, а если длительность неизвестна, спроси. Для смены времени передай `timeZone`, `checkConflicts: true`, `calendarsToCheck`; для вхождений серии — поля режима со смещением по [tools.md](tools.md#повтор-и-режимы-серии).
4. Напоминания меняй только по явной просьбе: полный новый набор, при добавлении или удалении одного — после чтения текущих, по [tools.md](tools.md#напоминания).

## Удалить

| Что удалить | Вызов |
| --- | --- |
| Одиночное Событие | `delete-event` с полученным ID |
| Одно вхождение | `delete-event` с ID записи из `list-events`, у которой есть `recurringEventId` и `id` отличается от него |
| Вся серия | `delete-event` с подтверждённым ID серии; после разделения серии каждая часть удаляется своим ID |
| Это и следующие | `update-event` серии с `modificationScope: "all"`: `RRULE` заканчивается через `UNTIL` до выбранного вхождения |

Если в ответе нет ID экземпляра, вхождение не удаляй наугад: назови ограничение и предложи изменить вхождение через `update-event` или удалить всю серию по явному выбору. Поля `status` для отмены в update нет.

Для «это и следующие» перечитай полное правило серии и исходное начало выбранного вхождения. Поставь включительную границу `UNTIL` строго раньше него: в типе даты или даты-времени правила, для timed повтора — в UTC. `COUNT` с `UNTIL` не совмещай; остальные условия правила и прошлые вхождения сохрани. Если RDATE, исключения, перенесённые вхождения или неясная граница не дают безопасно ограничить серию, остановись и назови ограничение; массовым удалением не заменяй. Если выбрано первое вхождение, «это и следующие» совпадает со всей серией — объясни это до выбора действия.

## Встреча из Inbox

`jedikit-tasks` передаёт Встречу с исходным ID и известными полями. Недостающие обязательные поля собери одним `clarify`, создай Событие и сделай Read-back. Верни `applied` с фактическим ID, календарём, датой, временем и ссылкой: исходный Inbox item отменяет `jedikit-tasks` по своим правилам, сам Inbox не меняй. При ошибке или `unverified` скажи, что создание не подтверждено и Inbox item должен остаться; create вслепую не повторяй.
