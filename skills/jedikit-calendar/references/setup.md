# Настройки, setup и status

Подключение Google Calendar, OAuth, scopes и установку инструментов выполняет владелец в Hermes. Скилл пользуется готовым MCP-сервером `google_calendar`, служебный календарь не создаёт и секретов не запрашивает.

## Настройки

В `memory` храни только эти значения:

| Настройка | Значение |
| --- | --- |
| Домашний пояс | Один IANA timezone, например `Europe/Moscow`. Бери известный пояс пользователя; не выводи его из языка и не принимай за него пояс календаря |
| Календарь записи | Один календарь, по умолчанию `primary`; храни фактический ID и аккаунт |
| Календари чтения | Выбранные ID и аккаунты; по умолчанию все видимые — перечитывай их через `list-calendars`, а не храни снимок списка |
| Границы дня | Начало и конец для Свободных окон, например 08:00–22:00; пример — не default и не норма |
| Зазор | Длительность между Бронью и Событием или Распорядком, выбранная пользователем; научного норматива нет |

Содержимое календаря, ID событий, состояние дня, сводки, Брони и Отметки не храни: источник состояния — провайдер.

Домашний пояс задаёт «сегодня», диапазоны вида и отчёты; пояс отдельного События его не меняет. Если границы дня пересекают полночь, покажи это в диапазоне.

Незаданный зазор при расчёте считай нулевым и показывай это, но как настройку не сохраняй. Зазор относится к размещению Броней: буферных записей он не создаёт и Распорядок не двигает. Ради обычного События или вида зазор не спрашивай.

## Где хранить настройки

- Только инструмент `memory` с `target="memory"`: одна компактная запись этого скилла, начинающаяся с `JediKit calendar:`. Отдельного чтения нет: текущие записи видны в контексте памяти.
- Записи с этим префиксом нет — `action="add"`, `content`. Есть — `action="replace"`, `old_text` (уникальный фрагмент этой записи) и `content` с полной новой записью: replace заменяет запись целиком, поэтому перенеси в неё все сохраняемые значения. Вторую запись не создавай, `target="user"` не используй.
- `done: true` — запись применена; это Read-back настроек. `staged: true` с `pending_id` — запись ждёт одобрения: скажи «Сохранение ждёт подтверждения памяти: `/memory pending`» и не называй настройку сохранённой. Отказ, например по лимиту, — `unapplied`; ответ без `done` и `staged` — `unverified`.
- Лимит около 2 200 символов на все записи памяти профиля: храни только выбранные значения и ID, остальное перечитывай у провайдера. При отказе по лимиту сообщи об этом; чужие записи не сокращай.
- Файлы скиллов JediKit (`SKILL.md`, `references/`, `tools.json`) только для чтения: не вызывай `skill_manage`, не создавай файлов настроек и не обходи `memory` другим способом, даже если подсказка Hermes советует хранить предпочтения в скилле.
- Если `memory` недоступен, настройки действуют только в текущем разговоре; сохранение не обещай.

## Setup и фразы о настройках

1. Прочитай известные настройки. Через `list-calendars` получи видимые календари, их ID, аккаунты и доступ записи из фактического ответа. Если право записи не видно, так и скажи; пробной записью его не проверяй. Чтение нескольких календарей не разрешает запись в них.
2. Defaults календарей принимай без переспроса. При нескольких аккаунтах и неоднозначном `primary` уточни личный аккаунт. Пояс, границы дня и зазор не выдумывай. В setup все отсутствующие настройки спроси одним `clarify`; в другом сценарии — только блокирующие его.
3. Фразы «мой день с 8 до 22», «живу по Москве», «читай эти календари, пиши в основной» — изменение настроек по [write-policy.md](write-policy.md). Относительные даты в настройки не превращай.
4. Сохрани выбранное по разделу [«Где хранить настройки»](#где-хранить-настройки) и покажи сохранённое и отсутствующее.

Setup не заводит задание утренней сводки — его заводит владелец Hermes; фоновые запуски настройки не сохраняют.

## Status

Покажи настройки из контекста памяти, недостающие значения и доступность инструментов по видимому списку или `tool_search`/`tool_describe`. На вопрос о календарях выполни `list-calendars` и сообщи фактический охват и ошибки. Успешное чтение подтверждает только чтение: OAuth и право записи по наличию инструмента не объявляй. Тестовых Событий не создавай, настройки не меняй.
