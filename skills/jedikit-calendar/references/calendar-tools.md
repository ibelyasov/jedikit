# Технический контракт Google Calendar

Инструменты предоставляет хост на сервере `google_calendar`. Разрешённый набор — [tools.json](../tools.json). Основа схем: [`nspady/google-calendar-mcp` v2.7.0](https://github.com/nspady/google-calendar-mcp/tree/3c3c36e129e2ff9fcd395a42578b057e6d85f721), npm `@cocal/google-calendar-mcp` 2.7.0. Это сторонний MCP для Google Calendar, не сервер Google. Схемы сняты без учётных данных Google; живые операции, полнота разворачивания серий и реакция на конфликты не подтверждены.

Сопоставляй `server` и базовое `name` со списком хоста; точные callable names и runtime schemas получай у хоста. Например, Hermes использует `mcp__google_calendar__<tool>` с `_` в префиксе и исходным именем инструмента. Если нужных tools нет, назови базовые имена и рекомендуй подключить средствами хоста. Не меняй OAuth, scopes или конфигурацию; не обходи инструменты через REST, terminal или собственный код. Наличие tool не доказывает авторизацию.

## Поля чтения

| Инструмент | Аргументы и ограничения |
| --- | --- |
| `list-calendars` | Обязательных полей нет. `account` — nickname или массив 1–10 nicknames; без него запрос всех подключённых аккаунтов |
| `list-events` | Обязателен `calendarId`: строка ID/имени либо массив 1–50 ID/имён без повторов. Передавай ID из `list-calendars`, а не неоднозначное имя. `timeMin`, `timeMax` — ISO 8601 без смещения; `timeZone` — IANA; `fields` — массив дополнительных полей |
| `get-event` | Обязательны строковые `calendarId`, `eventId`; `fields` добавляет поля к стандартным |
| `get-current-time` | Обязательных полей нет; передавай домашний `timeZone` (IANA), чтобы получить контекст «сегодня» и относительных дат перед поиском, созданием или изменением |

`account` у `list-events` допускает строку/массив как у `list-calendars`; у get и записей — только строку. Nickname соответствует `^[a-z0-9_-]{1,64}$`. При нескольких аккаунтах связывай календарь с его аккаунтом и передавай выбранный nickname: `primary` без такого контекста неоднозначен. Это личный Google Calendar, подключённый рабочий Outlook не обслуживается.

Стандартные поля list/get: `id`, `summary`, `start`, `end`, `status`, `htmlLink`, `location`, `attendees`. Для вида и идентификации роли явно запрашивай `fields: ["description", "recurringEventId", "originalStartTime", "recurrence", "transparency"]`; для нужного состояния можно добавить `updated`, `organizer`, `locked`. И list, и get поддерживают эти поля. Метки живут в `description`.

В схемах нет `pageToken`, `maxResults`, `singleEvents`, `orderBy` и поиска по тексту: не придумывай их. Получай диапазон через `timeMin`/`timeMax`, отбирай кандидатов по полученному ответу. Проверяй ошибки отдельных календарей и признаки неполноты; более 50 календарей читай несколькими запросами. Если ответ обрезан и продолжение недоступно, сужай диапазон разрешёнными чтениями или честно ограничивай охват. Отсутствие объекта в неполной выборке ничего не доказывает. Схема входа не гарантирует структуру ответа.

## Поля записи

| Инструмент | Обязательные и используемые поля |
| --- | --- |
| `create-event` | `calendarId`, `summary`, `start`, `end` — строки. Дополнительно по сценарию: `timeZone`, `description`, `location`, `recurrence`, `calendarsToCheck`, `allowDuplicates`, `duplicateSimilarityThreshold`, `sendUpdates` |
| `update-event` | Строки `calendarId`, `eventId`; передавай только изменяемые `summary`, `description`, `location`, `start`, `end`, `timeZone`, `recurrence`. Для серии: `modificationScope`, `originalStartTime`, `futureStartDate`. Для времени: `checkConflicts`, `calendarsToCheck`; всегда `sendUpdates` |
| `delete-event` | Строки `calendarId`, `eventId`; дополнительно `sendUpdates`. Полей режима серии нет |

Во всех трёх записях явно передавай `sendUpdates: "none"` (enum: `all`, `externalOnly`, `none`). У update/delete default — `all`, полагаться на него нельзя. Участников не добавляй, RSVP и приглашения не выполняй. Поля напоминаний, конференций, вложений и управления гостями вне сценариев. Не устанавливай `extendedProperties`: видимая строка в описании — единственная метка JediKit. При изменении описания сохраняй остальной текст и существующую метку, если пользователь не меняет её явно.

`start`/`end` для времени: `YYYY-MM-DDTHH:MM:SS` без смещения плюс явный `timeZone` IANA; для all-day: `YYYY-MM-DD`, конец эксклюзивный. Однодневное all-day заканчивается следующей датой. Схема также допускает строку с сериализованными `dateTime`/`timeZone` и datetime со смещением; для обычных сценариев используй простой формат выше и не смешивай смещение с поясом. Возвращённые даты интерпретируй по фактическому формату, не отбрасывай пояс. Конец позже начала, переход полуночи указывай следующей датой.

`recurrence` — массив строк RFC 5545, например `["RRULE:FREQ=WEEKLY;BYDAY=TU"]`. Сложный повтор передавай только при понятной семантике; не выдумывай окончание серии. `originalStartTime` и `futureStartDate` — ISO 8601 строки исходного/выбранного вхождения, не время после переноса.

| Режим update | Как выбрать объект |
| --- | --- |
| `thisEventOnly` | Подтверждённая серия и `originalStartTime` выбранного вхождения |
| `thisAndFollowing` | Подтверждённая серия и `futureStartDate` первого изменяемого вхождения |
| `all` | Подтверждённый ID серии |

Сопоставляй ID серии с `recurringEventId`, если он реально получен. ID экземпляра и полнота разворачивания повторов в list не проверены вживую; не конструируй ID из даты. Детали безопасного выбора и удаления — [events.md](events.md).

## Конфликты, дубли, неопределённый результат

`calendarsToCheck` — массив строковых ID календарей; для create и переноса передавай выбранные календари чтения, чтобы проверка не ограничилась календарём записи. У update `checkConflicts: true` сохраняет проверку при смене времени. Дополнительно читай нужный диапазон для собственного отображения пересечений; не считай это гарантией отсутствия гонок.

У create `allowDuplicates: false` по умолчанию блокирует почти точный дубль с similarity ≥ 0.95. `duplicateSimilarityThreshold` — число 0–1 (default 0.7 для обнаружения возможных дублей); это другой порог, не основание менять защиту. При отказе покажи найденное Событие одной строкой; `allowDuplicates: true` допустимо только после «создай всё равно» и проверки результата предыдущего вызова. Если ID дубля не дан, не придумывай его.

Статически описана проверка конфликтов, но не подтверждено, блокирует ли она запись или только предупреждает. Покажи фактический ответ, установи состояние Read-back; не двигай другие события, не отключай проверку ради успеха и не объявляй отказ без чтения при неясном ответе. `outcome_uncertain`, timeout или разрыв связи: чтение по известному ID либо диапазону, без повторной записи; неоднозначный результат остаётся `unverified`.
