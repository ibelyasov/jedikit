# План дня

Владельцы загружены по разделу «Вход в сценарий» `SKILL.md`; правила записи — там же, модель Брони — в [bookings.md](bookings.md#модель-брони).

## Прочитать день

1. **Время и настройки.** Через `get-current-time` сервера `google_calendar` определи сегодня и текущее время в домашнем поясе. Из настроек календаря, которые ведёт `jedikit-calendar`, возьми календари чтения, календарь записи, границы дня и зазор. Без границ дня покажи ленту без окон и одной строкой предложи сохранить границы через `jedikit-calendar`.
2. **Календарь.** Прочитай все календари чтения на день через `list-events` по правилам `jedikit-calendar`, вместе с описаниями: в них метки Броней и Распорядка. Продолжения страниц нет: при признаке усечения сужай диапазон по правилам `jedikit-calendar`, назови охват и ограничь вывод. События вне календаря записи тоже занимают время.
3. **Фокус-лист.** Открытые задачи SingularityApp, у которых `start` совпадает с выбранной датой в домашнем поясе: `task_list_today`, при необходимости `task_list` и `task_get`; семантику полей сверяй по `jedikit-tasks`. Весь Today без проверки `start` и просроченные задачи Фокус-листом не считай. Если Фокус-лист не выбран, предложи Daily open в `jedikit-tasks`, а не обход всех проектов.
4. **Ритуалы.** Через `jedikit-habits` прочитай Ритуалы из его настроек и время старта каждого — напоминание первой привычки. Если первая привычка не задана, возьми время из блока Распорядка этого Ритуала, а без блока покажи «время старта не установлено»; не спрашивай и не угадывай порядок. Длительности в Habitify нет: не выдумывай её и не создавай блок. Расхождение напоминания и блока Распорядка покажи, ничего не исправляй.

## Лента и окна

1. Покажи дату и пояс, затем хронологическую ленту Событий, Распорядка, Броней и Ритуалов; all-day — отдельно, пересечения отметь.
2. Выдели Свободные окна: промежутки внутри границ дня без Событий, Броней и Распорядка, за вычетом зазора от Событий и Распорядка. Для каждого окна — начало, конец, длительность. Для сегодня считай только будущее время. Своих буферов и норм заполнения дня не добавляй. Если неясно, занимает ли all-day время, назови это ограничение и не объявляй день свободным без оговорки.

## Вместимость

1. **Длительность.** `timeLength` бери, если задан; единицу и смысл сверяй по schema инструмента SingularityApp, преобразований не придумывай. Иначе дай грубую оценку «≈» без поправочных коэффициентов; если по тексту задачи оценить нельзя, обозначь неопределённость. Оценку в задачу записывай только по просьбе пользователя.
2. **Существующие Брони** учти один раз: покажи часть работы, покрытую будущими Бронями, и остаток; остаток сравни со Свободными окнами. Покрытием считай только Бронь внутри границ дня, без пересечений с другими Бронями, Событиями и Распорядком, с соблюдённым зазором. Связь с задачей проверяй по ссылке или ID и метке; совпадение названий связь не доказывает. Конфликтующие Брони покажи отдельно и до разрешения конфликта не вычитай. Прошедшую Бронь не вычитай: она не доказывает выполненную работу.
3. **Вердикт** давай осторожно: «По грубой оценке ≈5 ч работы без Броней, свободно 3 ч — скорее всего не влезает». Даже при достаточной сумме проверь, есть ли окна нужной длины: несколько коротких окон не равны одному длинному. Точного прогноза не обещай; задачи дроби только по решению пользователя.

## Предложить Брони

Предложи Брони для выбранных важных задач, а не для всего Фокус-листа, одним набором по [bookings.md](bookings.md#создать).

## Не влезает

Прямо скажи, что день не помещается; Распорядок ради задач не сокращай и не сдвигай. Одним набором предложи задачи для переноса на другую дату — с точной новой датой и причиной выбора. Срок ради вместимости не меняй; смену `start` выполняет `jedikit-tasks` по своим правилам. Набор вместе с Бронями показывай одним общим Preview.

## Результат

Лента и окна, оценки с их ограничениями, вердикт и согласованный набор изменений с итогом записи — либо отметка, что изменений не согласовано.
