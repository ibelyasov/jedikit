# План дня

Перед чтением и записью загрузи `SKILL.md` и правила записи `jedikit-calendar`, `jedikit-tasks`, а для Ритуалов — `jedikit-habits`, средствами хоста по имени. Операции каждого провайдера выполняй по его контракту.

## Источники дня

1. Определи сегодня и текущее время через `get-current-time` сервера `google_calendar` в домашнем часовом поясе. Возьми из настроек календаря календари чтения, календарь записи, границы дня и зазор между Бронью и Событием/Распорядком. Известное не переспрашивай. Если зазор не задан, считай его нулевым и покажи это в результате; без границ дня покажи ленту без окон и одной строкой предложи сохранить границы. Остальное блокирующее собери одним сообщением.
2. Прочитай все календари чтения на выбранный день через `list-events` по правилам `jedikit-calendar`, включая описания с метками Броней и Распорядка. Продолжения страниц в схеме нет: при признаке усечения сужай диапазон по правилам `jedikit-calendar`, сообщи охват и ограничь вывод. События вне выбранного календаря записи тоже занимают время.
3. Прочитай Фокус-лист в SingularityApp: открытые задачи, у которых `start` соответствует выбранной дате в домашнем поясе. Для сегодня используй `task_list_today`, при необходимости `task_list` и `task_get` сервера `singularity`, проверяя семантику полей по `jedikit-tasks`. Не считай весь Today Фокус-листом без проверки `start`, не включай просроченные автоматически. Если Фокус-лист ещё не выбран, предложи Daily open в `jedikit-tasks`; не заменяй его обходом всех проектов.
4. Через `jedikit-habits` прочитай Ритуалы и время старта: Области, отмеченные как Ритуалы в настройках, и напоминание первой привычки. Порядок не угадывай: если первая привычка не задана в настройках `jedikit-habits`, возьми время из блока Распорядка, а без него покажи «время старта не установлено» без вопроса. Длительности в Habitify нет. Покажи известное время; если блок Распорядка отсутствует, не выдумывай его длительность и не создавай его. При расхождении напоминания и календарного блока сообщи об этом, ничего не исправляй. Отдельные привычки Ритуала в календарь не добавляй.

## Лента и вместимость

1. Покажи дату и пояс, затем хронологическую ленту Событий, Распорядка и существующих Броней. All-day покажи отдельно, пересечения отметь. Для сегодняшнего остатка дня считай доступными только будущие промежутки внутри границ дня; прошедшее время не предлагай для работы.
2. Выдели Свободные окна без Событий, Броней и Распорядка, укажи начало, конец и длительность каждого. Отдельно учти заданный зазор от Событий и Распорядка: не представляй его как доступное для Брони время. Не добавляй собственных буферов и норм заполнения дня. Если смысл all-day для доступности неясен, обозначь ограничение, не объявляй день свободным без оговорки.
3. Для каждой задачи возьми `timeLength`, если он задан. Единицу и смысл значения проверь по runtime schema `jedikit-tasks`; не придумывай преобразование. Иначе дай грубую оценку с «≈», без поправочного коэффициента. При недостатке содержания задачи обозначь неопределённость. Не записывай оценку в задачу без просьбы пользователя.
4. Сопоставь объём задач и доступные окна. Уже забронированную работу учти один раз: покажи покрытую будущими Бронями часть и оставшуюся, сравни остаток со Свободными окнами. Покрытием считай только Брони внутри границ дня, без пересечений между собой, с Событиями и Распорядком, с соблюдённым зазором. Конфликтующие Брони покажи отдельно и до разрешения конфликта не вычитай из объёма задач; самостоятельно их не меняй. Привязку проверяй по ссылке/ID задачи и метке из [bookings.md](bookings.md); одинаковое название само по себе не доказывает связь. Прошедшую Бронь не вычитай из оценки оставшейся задачи: она не доказывает выполненную работу.
5. Дай осторожный вердикт, например: «По грубой оценке ≈5 ч работы без Броней, доступно 3 ч — скорее всего не влезает». Даже при достаточной сумме часов проверь, есть ли окна нужной длины: несколько коротких окон не равны одному длинному. Не обещай точного прогноза, не дроби задачи без решения пользователя.

## Выбор и изменения

Предложи Брони для выбранных важных задач, а не для всего Фокус-листа. Покажи один набор по [bookings.md](bookings.md): задачи, интервалы, длительности и предлагаемые изменения; одного «да» достаточно для показанного Preview.

Если день не помещается, так и скажи. Одним набором предложи задачи, которые можно сдвинуть на другую дату, с точными датами и причиной выбора. Срок задачи не меняй ради вместимости. Смену `start` выполняет `jedikit-tasks` по своим правилам. Никогда не предлагай сократить или сдвинуть Распорядок.

Если предложение включает Брони и смену дат задач, собери один общий Preview по обоим провайдерам, включая порядок записей и зависимости. Выполняй по правилам владельцев последовательно, остановись на первой ошибке; в общем результате раздели `applied`, `unapplied` и неподтверждённое. При перепланировании переноси или снимай только будущие Брони; прошедшие, уже начавшиеся, События и Распорядок не трогай.

Результат Плана дня: лента и окна, оценки и их ограничения, вердикт, выбранный набор изменений либо отсутствие согласованных изменений. Не называй предложенные Брони созданными до Read-back по правилам владельца.

## Сводка

Cron настраивает владелец. Запуск по расписанию или без участия пользователя только читает: не меняет провайдеров, память или расписание. Календарную часть утренней сводки отдаёт `jedikit-calendar` по своим правилам; planning добавляет к ней Фокус-лист и осторожный вердикт вместимости, обозначая доступные источники и неполноту. Применяй ограничения доставки владельцев скиллов; не включай личные тексты во внешнее уведомление без согласованной доставки. Не запускай создание Броней или перенос задач из фонового задания.
