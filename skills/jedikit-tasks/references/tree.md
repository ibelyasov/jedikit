# Setup, дерево и настройки

Записи — по [правилам записи](write-policy.md).

## Прочитай существующее устройство

Для setup нужны чтение проектов с ID, названием и родителем, а для выбранных новых объектов — создание проекта с назначением родителя. Прочитай настройки и актуальное дерево; отличай отсутствие настройки от недоступного чтения.

- Сначала определи области: проект верхнего уровня — область (`Работа`, `Личное` или выбранное пользователем название), даже если у него нет дочерних проектов. Область не требует результата или следующего шага.
- Ниже области проект с дочерними проектами — папка. Она может содержать одиночные задачи и не требует собственного результата или следующего шага. Крупное дело с дочерними проектами тоже считай папкой; следующие шаги относятся к дочерним проектам.
- Ниже области проект без дочерних проектов — проект: многошаговое дело с результатом и стартуемым следующим шагом, кроме режима `когда-нибудь`.

Покажи дерево по фактическим связям; одинаковые названия различай по пути и ID. Одиночные задачи размещай прямо в области или папке; не создавай проект `Общее`. Setup читает существующее устройство, не переименовывает, не перемещает и не мигрирует его.

## Дополни setup

1. Используй известные timezone, рабочие дни, окна обзоров и режимы областей или папок. Собери только блокирующие пробелы одним сообщением; необязательные настройки оставь неизвестными. Не угадывай настройки по названиям.
2. Если подходящих областей нет, предложи `Работа` и `Личное` либо названия пользователя. Подходящая существующая структура не требует переустройства.
3. Подготовь привязки режимов только к областям или существующим папкам по актуальному дереву. Для новых объектов укажи выбранные имя, родителя и место будущего ID. Новая папка требует хотя бы одного реального дочернего проекта в той же группе операций; иначе отложи привязку режима до появления дочернего проекта. Не создавай пометки или фиктивные дочерние проекты ради типа папки.
4. Полную явную команду создания объектов и изменения настроек выполни без Preview. Для одиночного предложения агента достаточно строки и «да»; для собранного агентом набора покажи один Preview: связи, режимы, порядок создания и привязки ID. Создай разрешённые объекты, получи их ID и выполни Read-back актуального дерева. Сохраняй привязки только когда Read-back подтвердил, что объект — область или папка с дочерним проектом.
5. Покажи полученное дерево, настройки и оставшиеся пробелы. Незавершённые части назови явно; при недоступной памяти используй ограниченный режим ниже.

## Применяй режим поддерева

Режим назначается области или папке и наследуется вниз от ближайшего явно настроенного предка. Не копируй унаследованный режим на каждый проект. Если режим не задан ни у одного предка, предложи пользователю выбрать его; не назначай `всегда` по умолчанию.

| Режим поддерева | Правило |
| --- | --- |
| `рабочие дни` | Включай в Daily open и Daily close только в выбранные рабочие дни по timezone пользователя. |
| `личные дни` | Включай в Daily open и Daily close в остальные дни недели: дополнение к рабочим дням без календаря праздников и догадок о выходных. |
| `всегда` | Включай в Daily open и Daily close независимо от дня недели. |
| `когда-нибудь` | Исключай из Daily open и Daily close, не требуй следующего шага; пересматривай раз в месяц. |

Режим не меняет даты, состояние задач или дерево провайдера. Не выводи его из возраста или количества задач. Для месячного обзора перейди к [обзорам](reviews.md).

## Настройки и status

Во встроенной памяти хоста сохраняй только timezone, выбранные рабочие дни, окна Daily open, Daily close, Weekly и месячного обзора `когда-нибудь`, явно выбранные режимы с ID областей или папок. Не сохраняй пометки папок, копии дерева или задач, фокус-листы, остатки и состояние обзоров. Тип объекта определяй по актуальному дереву. Если настроенный ID исчез или перестал соответствовать области либо папке, уточни привязку; не заменяй его по похожему названию.

Обычная фраза меняет настройки без специальной команды памяти: «теперь рабочие дни со вторника по субботу» или «пусть Личное будет всегда». Прочитай текущую настройку и разреши ID выбранного объекта. Если чтение, запись или подтверждение сохранения во встроенной памяти хоста недоступны, используй явно выбранные настройки текущего диалога: назови это ограниченным setup и не обещай сохранение между сессиями. Не заменяй память служебной задачей, проектом, тегом или файлом.

Для `status` прочитай список инструментов хоста и разрешённые настройки; при недоступной памяти покажи настройки текущего диалога. Не вызывай `get_my_context` и не читай задачи, проекты или данные аккаунта. Привязки ID покажи из настроек без проверки дерева. Сообщи доступность возможностей запрошенного сценария, встроенной памяти хоста и планировщика хоста, известные настройки и пробелы. Различай доступный инструмент, отсутствующий инструмент и неизвестное; наличие инструмента не доказывает рабочую авторизацию. Необязательные сведения могут остаться неизвестными или не настроенными.

Если пользователь выбрал приглашения через планировщик хоста, перейди к [Расписанию](reviews.md).
