# Дерево и Режимы поддерева

Тип объекта и режим определяй по актуальному дереву из `project_list`/`project_get`; пометок, служебных Тегов и записей в памяти для типа нет.

## Типы

| Тип | Как определить | Что требует |
| --- | --- | --- |
| Область | Проект верхнего уровня, даже без дочерних: `Работа`, `Личное` или выбранный пользователем | Ни результата, ни Следующего шага |
| Папка | Проект ниже Области, у которого есть дочерние проекты. Крупное дело, разбитое на подпроекты, тоже Папка; его шаги живут в подпроектах | Ни результата, ни Следующего шага; может держать одиночные задачи |
| Проект | Проект ниже Области без дочерних проектов | Результат и стартуемый Следующий шаг, кроме режима `когда-нибудь` |

Показывай дерево по фактическим связям; одинаковые названия различай по пути и ID. Одиночные задачи живут прямо в Области или Папке; проект `Общее` не создавай.

## Setup

Нужны чтение проектов с ID, названием и родителем, а для новых объектов — `project_create` с родителем. Прочитай настройки по [settings.md](settings.md) и актуальное дерево; отличай отсутствующую настройку от недоступного чтения.

1. Setup читает существующее устройство и не переименовывает, не перемещает и не мигрирует его. Подходящая структура не требует переустройства.
2. Используй известные timezone, рабочие дни, окна обзоров и режимы. Настройки по названиям не угадывай; необязательные оставь неизвестными.
3. Если подходящих Областей нет, предложи `Работа` и `Личное` или названия пользователя.
4. Режим привязывай только к Области или Папке по актуальному дереву. Для нового объекта укажи имя, родителя и место будущего ID. Новая Папка требует хотя бы одного реального дочернего проекта в той же Группе операций; иначе отложи привязку до его появления. Фиктивные дочерние проекты и пометки ради типа не создавай.
5. Preview набора, собранного агентом, показывает связи, режимы, порядок создания и привязку будущих ID.
6. Создай разрешённые объекты, получи их ID и перечитай дерево. Привязку режима сохраняй, только когда Read-back подтвердил Область или Папку с дочерним проектом.
7. Покажи дерево, настройки и оставшиеся пробелы; незавершённые части назови явно. При недоступной памяти работай как ограниченный setup по [settings.md](settings.md#изменение).

## Режимы поддерева

Режим назначается Области или Папке и наследуется вниз от ближайшего явно настроенного предка. На каждый проект его не копируй. Если режима нет ни у одного предка, предложи пользователю выбрать; `всегда` по умолчанию не назначай.

| Режим | Daily open и Daily close |
| --- | --- |
| `рабочие дни` | Только в выбранные рабочие дни по timezone пользователя |
| `личные дни` | В остальные дни недели; без календаря праздников и догадок о выходных |
| `всегда` | Независимо от дня недели |
| `когда-нибудь` | Не включается; Следующий шаг не нужен; пересмотр раз в месяц по [someday.md](someday.md) |

Режим не меняет даты, состояние задач и дерево в SingularityApp. Не выводи его из возраста или количества задач.
