# Операции

Назначение: выполнить setup, capture, triage и минимальную проверку проекта без скрытой миграции или импровизированных workflow.

## 1. Общий протокол записи

Перед workflow проверь нужные tools по [MCP-контракту](mcp-contract.md).

```text
одна явная обратимая запись
→ выполнить → прочитать результат обратно → сообщить

предложенная агентом запись или 2+ writes
→ полный preview → одно явное подтверждение
→ последовательные writes → read-back → ledger

первая ошибка
→ остановка → applied / error / unapplied → без rollback
```

Не считать «давай обсудим», «хочу» или ответ на уточнение подтверждением скрытого плана. Подтверждение должно следовать после preview и однозначно относиться ко всему показанному набору.

## 2. Setup

1. Проверь capabilities и выполни read-only `project_list`.
2. Покажи найденную иерархию. Не перестраивай существующие проекты.
3. Рекомендуй переиспользовать или создать root-контейнеры `Работа`, `Личное`, а внутри каждого — `Общее` для одиночных задач без реального проекта. Пользователь может выбрать дополнительные roots.
4. Собери по одному вопросу за turn: timezone; рабочие дни; окна daily open/close и weekly; режим каждого дополнительного root (`рабочие дни / личные дни / всегда`).
5. Покажи единый preview всех отсутствующих контейнеров и настроек.
6. После подтверждения создавай проекты последовательно: roots через `project_create(title)`, дочерние `Общее` через `project_create(title,parent)`.
7. Прочитай созданные проекты обратно и сохрани только их IDs/modes в native memory.

Root areas и `Общее` — контейнеры: не требуй у них результата и следующего шага. Не мигрируй старые задачи/проекты автоматически. При совпадающих названиях уточни по иерархии/ID, не создавай дубликат.

## 3. Capture

Явное «запиши/сохрани, чтобы не забыть» означает одну обратимую запись:

1. Возьми исходную пользовательскую фразу без улучшения.
2. Создай один Inbox item через `task_create(title)` без `projectId`, `start`, `deadline`, priority и metadata.
3. Прочитай item обратно и скажи, что это временное входящее до triage.

Не применяй capture к обычному вопросу, справочному ответу или фразе без просьбы сохранить.

## 4. Triage

Обрабатывай строго один item:

1. `task_list_inbox`, затем `task_get(id)` выбранного item.
2. Определи `task / project / idea / reference / meeting` по [ядру](core-method.md).
3. Предложи финальный title, destination и только обоснованные поля. Задай один вопрос с рекомендацией, если тип/destination неоднозначны.
4. Покажи preview. До подтверждения writes = 0.
5. Для задачи выполни `task_update(id,title,...)`, затем при необходимости `task_move(id,projectId)`.
6. Для проекта одним preview предложи `project_create` и ровно один `task_create` ближайшего шага.
7. После подтверждения raw title заменён. Не сохраняй raw в note, history, tag или metadata.

Idea/reference: спроси выбранное пользователем место и не создавай собственный список/процесс. Meeting: объясни границу календаря; отдельную задачу подготовки/follow-up создавай только по желанию пользователя.

## 5. Project

Для проверки реального проекта:

1. `project_get(id)` и `task_list(projectId)`; контейнер остановить с пояснением.
2. Коротко назвать ожидаемый результат из title/note, открытые задачи, явные блокеры и наличие стартуемого шага.
3. Если результата или шага нет, задать один вопрос и предложить вариант; не записывать без подтверждения.
4. Архив проекта — групповой preview. Все открытые задачи должны получить решение пользователя: `перенести / отменить / оставить проект активным`.
5. Только после обработки открытых задач вызвать `project_archive(id)` и проверить результат.

Завершение отдельной задачи не запускает project check и не создаёт новый шаг автоматически.

## 6. Внешние системы

Jira, CRM, email и другие рабочие системы остаются источником истины для своих объектов. В SingularityApp сохраняй только личное ближайшее действие и разрешённую ссылку/context. Не копируй статусы, историю и чужие обязательства и не меняй внешнюю систему.

Permanent delete, true batch, delayed/background writes, server prompts и backlog workflows не поддерживаются. Если сценария здесь нет, остановись и объясни границу.
