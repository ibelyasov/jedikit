# Настройки и status

## Что хранится

Во встроенной памяти хоста храни только настройки:

- timezone;
- выбранные рабочие дни;
- окна Daily open, Daily close, Weekly и месячного обзора Когда-нибудь;
- явно выбранные Режимы поддерева с ID Областей или Папок.

Не храни пометки Папок, копии дерева или задач, Фокус-листы, остатки и состояние обзоров. Тип объекта определяй по [дереву](tree.md). Если сохранённый ID исчез или перестал быть Областью или Папкой, уточни привязку; по похожему названию не заменяй.

## Где хранить настройки

- Только во встроенной памяти хоста. На Hermes это инструмент `memory` с целью `memory`: одна компактная запись с префиксом `JediKit tasks:`. Первая запись — `add`, если записи с этим префиксом ещё нет; изменение — `replace` по `old_text`, а не вторая запись. Если цели `memory` нет, назови ограничение; `user` и файлы вместо неё не используй.
- Файлы скиллов JediKit (`SKILL.md`, `references/`, `tools.json`) поставляет релиз, хост подключает их только для чтения. Не меняй их и не создавай рядом файлов настроек: не вызывай `skill_manage` и не пиши файловыми инструментами в каталог скиллов, даже если подсказка хоста советует хранить предпочтения в скилле. Если встроенная память хоста сама хранится в файлах, пиши ими только туда.
- Память хоста мала (на Hermes около 2 200 символов на все заметки): храни только выбранные значения и ID, остальное перечитывай у провайдера. При отказе по лимиту сообщи об этом; чужие записи не сокращай.
- Если хост поставил запись в очередь подтверждения (ответ `staged`, `pending_id`), скажи: «Сохранение ждёт подтверждения памяти хоста» (на Hermes — `/memory pending`) — и не утверждай, что настройка сохранена.
- Read-back — ответ инструмента памяти о применённой записи; без него результат `unverified`. Если памяти нет, настройки действуют только в текущем разговоре; сохранение не обещай.

## Изменение

Обычная фраза меняет настройку без особой команды: «теперь рабочие дни со вторника по субботу», «пусть Личное будет всегда». Прочитай текущую настройку, разреши ID объекта и запиши по [правилам записи](write-policy.md).

Если чтение, запись или подтверждение сохранения в памяти недоступны, используй явно выбранные настройки текущего диалога, назови это ограниченным setup и не обещай сохранение между сессиями. Не заменяй память служебной задачей, проектом, Тегом или файлом.

## Status

1. Прочитай список инструментов хоста и настройки; при недоступной памяти покажи настройки текущего диалога.
2. Не вызывай `get_my_context` и не читай задачи, проекты или данные аккаунта. Привязки ID покажи из настроек без проверки дерева.
3. Сообщи доступность возможностей запрошенного сценария, памяти и планировщика хоста, известные настройки и пробелы. Различай доступный, отсутствующий и неизвестный инструмент; наличие инструмента не доказывает рабочую авторизацию. Необязательное может остаться ненастроенным.

Приглашения через планировщик хоста — по [schedule.md](schedule.md).
