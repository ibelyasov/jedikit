# Разделы, Теги, Чек-лист

Каждое предложение об изменении структуры включает вариант «оставить как есть». Явную полную команду (например, объединить два названных Раздела) не переспрашивай; смысл уточняй, только если без него нельзя выбрать изменение. Удаления Разделов и Тегов среди инструментов нет: после переноса исходный объект остаётся, удаление — ручная операция в приложении с проверкой последствий. Объединение без удаления не объявляй полным.

## Разделы

Создание — `task_group_create`, изменение — `task_group_update`, чтение — `task_group_get`/`task_group_list`; Задачи перемещай через `task_move`, читай через `task_list`/`task_get`. Порядок Разделов не задаёт зависимостей; Раздел «Позже» не исключает Задачи из Today.

- Создать: в регулярно просматриваемом длинном Проекте видны реальные части. Покажи их Задачи и пользу названия; пустые шаблоны на каждый Проект не создавай.
- Объединить: Разделы одного Проекта с одинаковым смыслом мешают обзору. Выбери сохраняемый ID, покажи все перемещения и сохраняемые ID Задач.
- Переименовать: название расходится с подтверждённым содержимым. Покажи старый и новый текст, сохраняй узнаваемость.
- Удалить: только после признания Раздела ненужным и решения по каждой его Задаче. Пустота, возраст или похожее название — лишь повод проверить назначение.

Часть с самостоятельным результатом и отдельным обзором — Проект, а не Раздел.

## Теги

Создание — `tag_create`, изменение — `tag_update`, чтение — `tag_get`/`tag_list`; связи Задач меняй полями `task_update`, Задачи читай через `task_get`/`task_list`.

- Создать: повторяющийся вопрос выбора поперёк Проектов. Проверь существующие Теги и доступные фильтры, покажи подходящие Задачи. Тег на каждый Capture не ставь; название Проекта, дату или приоритет без отдельной пользы не дублируй.
- Объединить: Теги с одинаковым смыслом. Сравни связанные Задачи, ссылки фильтров, дочерние Теги, архивные и повторяющиеся элементы, Favorites. Выбери сохраняемый ID и покажи изменения связей с сохранением ID Задач и остальных Тегов.
- Переименовать: опечатка, неясное название или согласованная смена словаря. Покажи старый и новый текст и затрагиваемые ссылки.
- Удалить: только если пользователь больше не использует Тег для выбора или поиска. Проверь тот же охват, что для объединения; ноль видимых Задач не доказывает неиспользование.

Если фильтры, Favorites, дочерние Теги, архивные или повторяющиеся элементы не читаются, назови пробел: объединение или удаление требует ручной проверки. Служебные Теги состояния агента не создавай; пользовательский Тег не удаляй лишь из-за имени.

## Чек-лист

1. Чек-лист — памятка внутри одной Задачи. Самостоятельные действия или пункты с собственными датами и Тегами — Задачи Проекта.
2. Используй `checklist_item_create`, `checklist_item_update`, `checklist_item_check` или `checklist_item_uncheck`; читай через `checklist_item_get`/`checklist_item_list`. Поля привязки к Задаче и порядка передавай лишь при создании или перестановке пункта.
3. Покажи точные пункты и изменения. Отмена пункта — не то же, что снятие отметки. Отметка пункта не завершает Задачу.
