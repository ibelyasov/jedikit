# Задача

## Формулировка

Задача — одно физическое действие: конкретный глагол, объект и видимый признак готовности. Пример: «Отправить Анне смету; письмо со сметой отправлено». Признак готовности сохраняй в тексте задачи. Неопределённое «заняться ремонтом» не превращай в список обещаний; несколько самостоятельных действий ради результата — Проект по [projects.md](projects.md).

Существующие даты, приоритет и длительность при переформулировке сохраняй.

## Трудный старт

Проверь, можно ли начать задачу сейчас. Если она зависла, по известному препятствию предложи меньший шаг, уточнение недостающего ресурса или отказ от обязательства. Спрашивай только то, без чего нельзя выбрать действие; объяснять трудность старта пользователь не обязан. Диагнозов не ставь и выполнения после переформулировки не обещай.

По желанию пользователя предложи if–then: «если [наблюдаемая ситуация], то [доступное действие]», без обязательной даты.

## Даты, приоритет и длительность

Их выбирает пользователь; меняй только выбранное, не обнуляй ради чистовой формулировки. Поля — по [контракту инструментов](tools.md#поля-и-значения).

- Срок (`deadline`) — внешний жёсткий срок с последствиями пропуска. Плановая дата (`start`) — день, который пользователь сам выбрал для начала. Прогноз не превращай в Срок и задачу молча не переноси.
- Срочность обсуждай через цену пропуска срока, а не только близость даты.
- Оценка длительности — прогноз с неопределённостью, не обязательство. Сохраняй её по выбору пользователя; универсальную длительность или множитель не назначай.

## Состояние

1. Найди задачу через `task_get` или `task_list`; установи текущее состояние, повторение и последствия изменения.
2. Выполнена — `task_complete`. Отметка выполнения только на сегодня, если её выбрал пользователь, — `task_complete_today`; она не завершает задачу окончательно. Снять выполнение — `task_uncomplete`, если применимо к текущему состоянию.
3. Отказ — `task_cancel`. Архив — `task_archive`, возврат — `task_unarchive`. Архив не удаляет задачу; возврат не восстанавливает прежние даты, повторения и другие поля.
4. Read-back — чтением, которое показывает новое состояние.
5. После выполнения Следующий шаг автоматически не создавай. Если у Проекта шага больше нет, предложи выбрать его отдельно.
