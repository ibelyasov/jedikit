# Проекты, Разделы, Теги и Чек-листы

Записи — по [правилам записи](write-policy.md).

## Осмотр Проекта

1. Прочитай выбранный объект через `project_get`, дерево через `project_list` и открытые Задачи через `task_list`.
2. Определи тип объекта и наследуемый режим по [дереву и режимам](tree.md).
3. Покажи результат Проекта, открытые Задачи, препятствия и Следующий шаг. Если без неизвестного результата нельзя выполнить запрос, включи его в сообщение со всеми блокирующими пробелами. Число завершённых Задач не доказывает достижение результата.
4. Для активного Проекта используй выбранный стартуемый Следующий шаг; если его нет, предложи один, два допустимы при независимости и параллельности. Не придумывай полный будущий план.
5. Для формулировки, трудного старта или if–then используй [правила Задачи](inbox.md). Переиспользуй существующую Задачу через `task_update` или `task_move`; новую создавай через `task_create`. Не копируй Задачи ради организации.

## Создание и изменение Проекта

1. Для многошагового дела используй заданные результат, место в дереве и Следующий шаг; запроси только блокирующие пробелы одним сообщением. Для выбора места или режима используй [дерево](tree.md).
2. Используй `project_create` для создания или `project_update` для изменения; добавь только нужные `project_get` или `project_list` для выбора объекта и родителя. Поля родителя и заметки нужны лишь при соответствующем изменении.
3. Полную явную команду выполни без Preview. Одиночное предложение агента — одна строка и «да»; набор, собранный агентом, — один Preview с родителем, названием, результатом и точными изменениями Задач. При записи результата сохраняй прежний текст заметки.
4. Создай или измени Проект, затем выполняй разрешённые операции над Задачами с полученными ID.

## Изменение состояния Задачи

1. По явной команде найди Задачу через нужное `task_get` или `task_list`. Установи текущее состояние, повторение и последствия выбранного изменения.
2. Для выполненной Задачи используй `task_complete`; для временной отметки выполнения на сегодня — `task_complete_today`, если именно это выбрал пользователь. Такая отметка не означает окончательного завершения. Для снятия выполнения используй `task_uncomplete`, если он применим к текущему состоянию.
3. При отказе используй `task_cancel`. Для помещения в архив используй `task_archive`, для возврата — `task_unarchive`. Архив не удаляет Задачу; возврат не восстанавливает автоматически прежние даты, повторения или другие поля.
4. Выбери инструмент изменения и чтение, показывающее новое состояние Задачи.
5. После завершения не создавай Следующий шаг автоматически. Если у Проекта его больше нет, предложи выбрать отдельно.

## Закрытие или отказ

1. Прочитай Проект, открытые Задачи и дочерние Проекты. Для Папки используй заданные решения по всему затронутому дереву; запроси только недостающие вместе с другими блокирующими пробелами.
2. При завершении проверь результат. При отказе не требуй объяснения причины. Изменение видимой заметки через `project_update` включай только если пользователь выбрал сохранить причину; прежние данные сохраняй.
3. Используй решение по каждой открытой Задаче: завершить выполненную, перенести нужную, отменить ненужную или явно оставить открытой в архиве. Неизвестные решения собери одним сообщением. Используй только выбранные `task_complete`, `task_cancel`, `task_move` или `task_update` по правилам состояния выше. Не отменяй список молча.
4. Выясни охват `project_archive`: потомки, открытые и повторяемые Задачи. Если последствия неизвестны, предложи ручную операцию в приложении.
5. Полную явную команду выполни без Preview; для набора, собранного агентом, покажи один Preview: выбранное изменение заметки, судьба каждой Задачи, последствия архива. Выполни разрешённые изменения заметки и Задач; вызови `project_archive` последним.
6. Для явного возврата используй `project_unarchive` с установленным охватом. Не обещай восстановление прежних состояний или повторений; дополнительные изменения повторений предложи по правилам записи, если они не выбраны явно.

## Разделы

Выбери `task_group_create` для создания или `task_group_update` для изменения; добавь нужные `task_group_get` или `task_group_list`. Для перемещений используй `task_move`, для чтения Задач — нужные `task_list` или `task_get`. Порядок Разделов не задаёт зависимости, а название «Позже» не исключает Задачи из Today.

- Предложи создать Раздел, если в регулярно просматриваемом длинном Проекте видны реальные части. Покажи существующие Задачи и пользу названия; не создавай пустые шаблоны на каждый Проект.
- Предложи объединить Разделы одного Проекта, если их одинаковый смысл известен и разделение мешает обзору; уточняй смысл только если без него нельзя выбрать изменение. Явную полную команду объединения не переспрашивай. Выбери сохраняемый ID, покажи все перемещения и сохраняемые ID Задач.
- Предложи переименовать Раздел, если название расходится с подтверждённым содержимым. Покажи точный старый и новый текст; сохраняй узнаваемость.
- Предложи удалить Раздел после признания его ненужным и решения по каждой Задаче. Пустота, возраст или похожее название — повод проверить назначение.

Оставь вариант «оставить как есть» в каждом предложении. Удаления Раздела среди этих инструментов нет: после перемещений исходный Раздел остаётся. Сообщи, что объединение неполное и удаление требует ручной операции в приложении с проверкой последствий. Если часть имеет самостоятельный результат и отдельный обзор, предложи Проект вместо Раздела.

## Теги

Выбери `tag_create` для создания или `tag_update` для изменения; добавь нужные `tag_get` или `tag_list`. При изменении связей используй соответствующие поля `task_update`; при чтении Задач — нужные `task_get` или `task_list`.

- Предложи создать Тег для повторяющегося вопроса выбора поперёк Проектов. Проверь существующие Теги и доступные фильтры, покажи подходящие Задачи. Не назначай Теги каждому Capture и не дублируй название Проекта, дату или приоритет без отдельной пользы.
- Предложи объединить Теги при известном одинаковом смысле; уточняй его только если без него нельзя выбрать изменение. Явную полную команду объединения не переспрашивай. Сравни связанные Задачи, ссылки фильтров, дочерние Теги, архивные и повторяемые элементы и Favorites. Выбери сохраняемый ID. Покажи изменения связей с сохранением ID Задач и остальных Тегов.
- Предложи переименовать Тег при понятной опечатке, неясном названии или согласованной смене словаря. Покажи старый и новый текст и затрагиваемые ссылки.
- Предложи удалить Тег, только если пользователь больше не использует его для выбора или поиска. Проверь тот же охват, что для объединения. Ноль видимых Задач не доказывает неиспользование.

Оставь вариант «оставить как есть» в каждом предложении. При недоступности фильтров, Favorites, дочерних Тегов, архивных или повторяемых элементов назови пробел: объединение или удаление требует ручной проверки. Удаления Тега среди этих инструментов нет: перенос связей не удаляет исходный Тег. Назови оставшиеся ручные операции с фильтрами и удалением; не объявляй объединение полным. Не создавай служебные Теги состояния агента; не удаляй пользовательский Тег лишь из-за имени.

## Чек-лист

1. Используй Чек-лист как памятку внутри одной Задачи. Для самостоятельных действий или пунктов с собственными датами и Тегами предложи Задачи Проекта.
2. Выбери `checklist_item_create`, `checklist_item_update`, `checklist_item_check` или `checklist_item_uncheck` для нужного изменения. Добавь только нужные `checklist_item_get` или `checklist_item_list`. Используй поля привязки к Задаче и порядка лишь при создании или перестановке пункта.
3. Покажи точные пункты и изменения. Не приравнивай отмену пункта к снятию отметки. Отметка пункта не завершает всю Задачу автоматически.
