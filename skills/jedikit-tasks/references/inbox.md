# Inbox: Capture, Triage, Inbox debt

## Capture

На «запиши», «сохрани во Inbox» или равнозначную просьбу:

1. Возьми текст как есть: без Triage и чистовой формулировки.
2. Создай ровно один Inbox item через `task_create` без проекта, дат, приоритета, длительности и добавленного содержания. Даты и детали из текста оставь текстом. Если создание требует других значений, не назначай их по догадке.
3. Выполни Read-back и сообщи, что запись во Inbox, с её ID.

Обычный вопрос или справку без просьбы сохранить не записывай. Нет текста — спроси, что записать. Несколько явно названных записей сохрани без классификации как Группу операций.

## Triage

Один Inbox item за раз. Нужны чтение Inbox, задачи и дерева, изменение текста и места с сохранением ID.

1. Прочитай выбранный Inbox item и его ID. Если записей несколько и выбор не задан, включи выбор в блокирующие пробелы. Прочтение — ещё не завершённый Triage.
2. Определи тип: Задача, Проект, Идея, Справка или Встреча. Используй уже заданный тип; при неоднозначности оставь запись во Inbox до ответа.
3. Задача: используй заданные чистовую формулировку, первый доступный шаг и место по [дереву](tree.md); формулируй по [tasks.md](tasks.md#формулировка). Проект, Идею, Справку и Встречу веди по подразделам ниже.
4. Для Задачи измени исходный Inbox item через `task_update`/`task_move`, сохранив ID; копию прежней формулировки не создавай.
5. Read-back подтверждает место и тот же ID. Следующую запись разбирай, только если она входит в выбранный пользователем набор; такой набор веди последовательно без вопроса о продолжении.

Отказ от формулировки оставляет запись без изменений. Отказ от самого обязательства — `task_cancel` по [tasks.md](tasks.md#состояние). Разобранную Идею, Справку или Встречу не удаляй и не отмечай выполненной: её Inbox item отменяется.

### Проект из Inbox item

Несколько самостоятельных действий ради одного результата — Проект.

1. Используй известные результат, место и Следующий шаг по [projects.md](projects.md). Если шаг неизвестен, предложи конкретное действие по его определению.
2. Если подходящий Проект уже есть, предложи поместить Inbox item туда; дубликат проекта не создавай.
3. Новый Проект — Группа операций: `project_create` в выбранной Области или Папке, получить ID, превратить исходный Inbox item в Следующий шаг и поместить в Проект. Preview набора, собранного агентом, показывает будущую привязку ID проекта и сохранение исходного ID задачи.
4. Дополнительный выбранный Следующий шаг включи в ту же группу.

При частичном результате может остаться Проект без шага, а исходная запись — во Inbox; покажи фактическое положение каждого объекта. Для режима `когда-нибудь` Следующий шаг не нужен; используй смысл и формулировку исходной записи и уточняй только блокирующую неоднозначность.

### Идея или Справка

1. Подскажи, куда перенести: Идею — туда, где пользователь решает, стоит ли действовать; Справку — туда, где он её найдёт. Переносит пользователь.
2. Пока пользователь не сообщил о переносе, Inbox item не меняй. Намерение перенести — не перенос.
3. «Перенёс, отмени» при однозначном ID — сразу `task_cancel` и Read-back. Одно «перенёс» — одна строка «Отменить Inbox item <ID>?» и отмена после «Да». Это же действует для Встречи, которую пользователь перенёс в календарь сам.

### Встреча

Встреча — Inbox item с договорённостью и временем. Намерение без договорённости — Задача.

1. Передай Встречу `jedikit-calendar` с исходным ID и известными данными: загрузи его `skill_view(name=…)` с тем же префиксом, что у имени этого скилла (`agent-plugin-jedikit-805a716c:jedikit-tasks` → `agent-plugin-jedikit-805a716c:jedikit-calendar`, голое `jedikit-tasks` → `jedikit-calendar`), затем `skill_view(name=<то же имя>, file_path="references/write-policy.md")` и создавай Событие по ним. Если скилл недоступен, назови ограничение и оставь Inbox item.
2. Недостающие поля События собирает `jedikit-calendar`. Если дата неизвестна или договорённости нет, одной строкой предложи сохранить это Задачей с действием уточнения и выполни после «Да».
3. Явная команда переноса — создание События и отмена Inbox item подряд без Preview; в наборе, собранном агентом, обе операции входят в один общий Preview.
4. `task_cancel` исходного ID и его Read-back выполняй только после того, как `jedikit-calendar` вернул созданное и перечитанное Событие (`applied`). Если Событие не создано или не подтверждено, Inbox item остаётся. Если отмена не удалась, сообщи: Событие создано, исходная запись не отменена или её состояние неизвестно. Без повтора и отката.

Слова пользователя не подтверждают незавершённую запись через `jedikit-calendar`; ручной перенос — по правилу Идеи и Справки.

## Inbox debt

Предложи отдельную сессию Triage на 15 минут; если тяжело — на 10 или 5. Прочитай Inbox через `task_list_inbox` и разбирай по одному по [Triage](#triage). В конце покажи остаток. Дополнительное приглашение `cronjob_manage` согласуй отдельно по [schedule.md](schedule.md).
