# Обзоры

Записи — по [правилам записи](write-policy.md).

## Начало обзора

1. Прочитай соответствующие обзору настройки и Режимы поддеревьев по [дереву и встроенной памяти хоста](tree.md). Не задавай режим по умолчанию.
2. В обоих Daily применяй правила включения из дерева ко всем кандидатам, хвостам, остаткам и затронутым Проектам по дню обзора; наличие Срока их не отменяет.
3. Не задавай фиксированный предел Фокус-листа или обзора. Не читай календарь и не обещай вместимость Фокус-листа. Скажи: «Календарь и доступное время не проверены».
4. Для решений о датах, длительности и приоритете используй [правила Задачи](inbox.md); для результата, состояния и Следующего шага — [осмотр Проекта](projects.md).

## Daily open

1. Определи сегодня в согласованном часовом поясе. Прочитай вчерашние хвосты через `task_list_overdue`, затем Today через `task_list_today`.
2. Используй уже названный Ресурс дня; если он неизвестен, спроси: `низкий / обычный / высокий`. По самооценке предложи более короткий или широкий Фокус-лист; не вычисляй ресурс из числа Задач.
3. Отфильтруй хвосты и Today по наследуемым режимам. Если нужны другие кандидатуры, прочитай открытые Задачи подходящих поддеревьев через `task_list` и Проекты через `project_get`. Не обходи всё дерево без необходимости.
4. Выбери с пользователем стартуемые Задачи. При трудном старте используй соответствующий сценарий [Triage](inbox.md).
5. Собери решения по выбранным Задачам и исключённым из Фокус-листа хвостам/Задачам Today в допустимых режимах. Выбранным предложи `start=today`; для исключённых получи решение: оставить, снять Плановую дату, назначить дату пользователя или отменить после отказа. Используй `task_update`, при отмене — `task_cancel`, при перемещении — `task_move`.
6. Полные явные команды выполни без Preview. Для собранного агентом набора покажи один Preview: выбранные Задачи с `start=today` и решения по исключённым; одиночное предложение — строка и «да». «Оставить» не требует записи или подтверждения. Выполни разрешённые изменения и покажи Фокус-лист.

## Daily close

1. Назови день обзора. Прочитай остатки через `task_list_today`, `task_list_overdue` и при необходимости `task_list`; отфильтруй по наследуемым режимам. Для другого дня уточни недостающее у пользователя: Today не является историческим снимком.
2. Используй известное решение по каждому остатку: оставить, снять Плановую дату, перенести на дату пользователя, завершить выполненное или отменить после отказа. Все недостающие решения собери одним сообщением. Подготовь выбранные изменения `task_update`, `task_complete` или `task_cancel`.
3. Выдели затронутые Проекты из диалога и доступных изменений Задач. Фильтр изменений `task_list` используй только при его наличии; при неполной истории спроси, какие Проекты затронуты.
4. Прочитай подходящие по режимам Проекты через `project_get` и дерево через `project_list`. Проведи [осмотр Проекта](projects.md) и подготовь предложенные изменения.
5. Проведи Гвоздодёр: попроси прокрутить день назад от вечера к утру — места, разговоры, сообщения и переключения — и назвать незаписанные мысли или обязательства.
6. Используй [Capture](inbox.md) только по явной просьбе записать либо включи предложенные записи в будущую группу. Не превращай произнесённую мысль в запись автоматически.
7. Выполни полные явные команды без Preview. Для набора предложенных изменений остатков, Проектов и ещё не записанных Capture покажи один Preview; одиночное предложение — строка и «да». Выполни разрешённые изменения и сообщи результат; не повторяй уже выполненные явные команды.

## Weekly

1. Прочитай Inbox через `task_list_inbox`. Разбирай Inbox items по одному по [Triage](inbox.md). Inbox debt вынеси в отдельные сессии; не объявляй неразобранные записи обработанными.
2. Прочитай всё доступное дерево через `project_list`. Пройди все Области и Папки, включая их одиночные Задачи; не ограничивай обзор затронутыми сегодня Проектами.
3. Для каждого активного Проекта прочитай `project_get` и открытые Задачи через `task_list`. Проведи [осмотр Проекта](projects.md), сравни движение к результату и подготовь изменения.
4. Перечисли поддеревья Когда-нибудь и согласованное окно ежемесячного обзора, если известно из настроек. Не включай их в активный выбор недели; на ежемесячном обзоре проверь их все.
5. Проверь актуальность открытых Задач и известных Сроков, включая просроченные через `task_list_overdue`. Не составляй обязательную недельную квоту.
6. Подготовь предложения по Разделам и Тегам по [правилам структуры Проекта](projects.md).
7. Полные явные команды выполни без Preview; набор предложенных изменений по итогам обхода собери в один Preview, одиночное предложение — строка и «да». Выполни разрешённые изменения. Triage Inbox items остаётся разбором по одному; выбранный пользователем набор продолжай последовательно без отдельного вопроса. Не повторяй уже выполненные изменения.
8. Сообщи охват, оставшиеся решения и ограничения.

## Ежемесячный обзор Когда-нибудь

1. Прочитай через `project_list` все поддеревья Когда-нибудь. Обойди их по Папкам; прочитай Проекты и Задачи через `project_get` и `task_list`.
2. Используй известное решение об актуальности дела: оставить в Когда-нибудь, вернуть в активный Режим поддерева, завершить или отказаться; недостающие решения собери одним сообщением. Для изменения режима используй [дерево](tree.md), для возвращаемого Проекта — [осмотр Проекта](projects.md).
3. Подготовь точные изменения настроек режима и объектов. Для завершения или отказа используй [закрытие Проекта](projects.md).
4. Полные явные команды выполни без Preview; для набора предложенных изменений покажи один Preview, для одиночного — строку и «да». Выполни разрешённые изменения.

## Inbox debt

Предложи отдельную сессию Triage на 15 минут; если тяжело, предложи 10 или 5. Прочитай Inbox через `task_list_inbox`, разбирай по одному по [Triage](inbox.md). По окончании покажи остаток. Дополнительное приглашение планировщика хоста согласуй отдельно.

## Расписание

1. Используй планировщик хоста; при его отсутствии объясни ограничение.
2. Установи часовой пояс, частоту, окно, место доставки и точный текст задания; включи эти параметры в Preview, если он требуется по правилам записи.
3. Текст задания начинай с точного маркера `[расписание jedikit]`, затем направляй к чтению для приглашения открыть Daily open, Daily close, Weekly или ежемесячный обзор Когда-нибудь. Применяй правило фонового запуска из [правил записи](write-policy.md#разрешение-на-запись).
4. Во внешнем уведомлении показывай только количества и короткое приглашение. Названия Задач и Проектов добавляй лишь после отдельного согласия на такую доставку; без него не включай тексты или заметки. При ошибке подключения сообщи безопасную ошибку без секретов.
5. Не объявляй Weekly пропущенным: приглашение не доказывает, что обзор состоялся.
