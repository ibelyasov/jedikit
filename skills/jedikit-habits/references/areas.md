# Области Habitify

Область помогает видеть выбранные привычки вместе. Это отдельная группа Habitify, без дерева, наследуемых режимов или проектов SingularityApp. Не обещай ускоренное формирование, здоровье, снижение нагрузки или «баланс жизни» благодаря группе либо цвету. Возможное удобство фильтра оценивает пользователь. Область, выбранная как ритуал, ведётся по [rituals.md](rituals.md); её ID — настройка встроенной памяти хоста.

Операции и согласие выполняй по [operation-policy.md](operation-policy.md), технический контракт — по [habitify-tools.md](habitify-tools.md). При сигналах риска примени [safety.md](safety.md): классификация не заменяет помощь человеку.

## Когда предложить

При setup/status или обзоре предложи один небольшой вариант, если наблюдается потребность: появилась следующая привычка сходного назначения, пользователь ищет связанные привычки или жалуется на длинный список. Назови конкретную пользу: «Эти две привычки удобно видеть вместе. Добавить их в выбранную область?» Число привычек — эвристика, а не обязательный порог.

Для одной привычки без запроса на группировку пропусти организацию. Не заполняй все сферы, не назначай квоты и не повторяй отклонённое предложение без новой потребности. Если вопрос только о времени дня, сначала рассматривай имеющийся Time of Day; это отдельный объект, не область и не напоминание.

Группировка существующих привычек не разрешает новые поведения, изменение планов или отметки. Сохраняй один эксперимент; на его обзоре меняй одну вещь. Область не заменяет конкретный сигнал действия, if–then или Safety-стоп.

## Выбрать область и название

1. Прочитай `list-areas` и выбранные привычки через `get-habit`. Проверь полноту списка и принадлежность объектов. Неоднозначный объект и остальные блокирующие пробелы уточни одним сообщением. Для открытого запроса сначала предложи подходящую существующую область, затем при необходимости новую. Явный однозначный выбор не пересогласовывай. Не создавай дубль и не назначай область скрыто по похожим названиям.
2. Для новой области используй заданный `name` и известное предпочтение пользователя; отсутствующее обязательное имя запроси вместе с другими блокирующими данными. Для чувствительного содержания предложи нейтральное имя вроде «Личное»; не добавляй диагноз или приватную интерпретацию без запроса. Названия областей видны в приложении, их отображение в уведомлениях неизвестно — скрытие не гарантируй. Не переименовывай существующие объекты сам.
3. `colorHex` и `icon` необязательны; не требуй их ради группировки. Для `create-area` обязателен `name`; для `update-area` меняй только выбранные поля. Точные типы, вложенность и аргументы бери из inputSchema хоста. После создания возьми `id` из ответа и прочитай `get-area`; после изменения сверь новые и сохранённые поля через `get-area`.

## Назначить или снять связь

Перед `update-habit` получи свежий `get-habit`. Установи полный текущий набор `areas[].id`, вычисли будущий набор с сохранением всех остальных назначений и передай **весь** `areaIds`: это замена набора, а не добавление одного ID. Для снятия выбранной связи исключи только её. Не отправляй `[]` или `null` для неоговорённого очищения.

Применяй guard **всей writable-конфигурации** из habitify-tools.md, сохраняя остальные поля привычки, цели, расписание, напоминания и `timeOfDayIds`. При неполных данных, неоднозначном преобразовании или необходимости догадки остановись до записи и предложи ручное изменение в приложении. После записи независимо прочитай `get-habit`, сравни полный набор `areas[].id` с ожидаемым и проверь сохранность прочей конфигурации; порядок ID не является изменением состава. Несовпадение либо недостаток данных означает `unverified`, без повтора или отката.

## Согласие и выполнение

Явную полную одиночную команду или явно названную группу выполняй после исходного чтения без Preview, затем Read-back; не добавляй соседнюю группировку. Все блокирующие пробелы собери одним сообщением; известное и необязательное не спрашивай. Исключение — `delete-area` по правилам ниже.

Для одиночного предложения агента достаточно одной строки с объектом, изменением и последствиями, затем «да». Для набора, собранного агентом, покажи один Preview: области/ID, привычки/ID, старые → новые названия, полный старый → новый набор назначений, поля, последствия и порядок операций. Существенное изменение предложения требует обновлённого согласия; полная явная поправка пользователя уже задаёт обратимое изменение.

Создание области и назначение её привычкам — группа: `create-area` → `get-area`, затем для каждой привычки `update-habit` с ID из ответа → `get-habit`. Полную явную группу выполняй сразу; для набора, собранного агентом, нужен один Preview и одно подтверждение всех зависимых назначений. Кнопка допуска хоста остаётся отдельным слоем по operation-policy.md.

Проверь инструменты каждого этапа, включая Read-back, до первой записи. Выполняй запись → Read-back последовательно для каждого объекта. При первой ошибке, отказе хоста, неизвестном исходе или несовпадении останови группу; адресно прочитай состояние без слепого повтора. Отчёт различает `applied` / `unverified` / `unapplied`, включая не начатые операции. Не используй bulk, параллельные записи, автоматические повторы или откат; список на чтение сам по себе не разрешает записи. Явный запрос на ритуал выбирает его состав по rituals.md.

Если исход `create-area` неизвестен и ID не получен, прочитай полный `list-areas` и найди выбранный `name` по разделу [«Неизвестный исход создания»](habitify-tools.md#неизвестный-исход-создания). Покажи найденные совпадения; совпадение или неполнота списка означают `unverified`. Не подставляй ID совпадения в зависимые назначения автоматически: группа остановлена, оставшиеся записи `unapplied`. Новое создание возможно только после явного решения пользователя. Отказ на кнопке хоста также останавливает группу; результат отклонённого вызова и оставшихся записей определи по operation-policy.md, не выполняй их повторно.

## Удалить область

`delete-area` доступен только по **явной просьбе пользователя**, после однострочного подтверждения безвозвратной потери области и связей с ней, даже для одной буквальной команды. Агент не инициирует удаление: пустота, возраст или сходство названий его не разрешают. Подтверждение группы с перечисленными потерями достаточно без дополнительных подтверждений каждой операции.

До подтверждения прочитай выбранную область и **все страницы связанных активных и архивных привычек** через `list-habits` с `areaId`, отдельно `archived=false` и `archived=true`. Правила полноты — в habitify-tools.md. Получи адресные `get-habit` и сохрани полные наборы назначений затронутых привычек в текущем разговоре. Если фильтры, полнота или связи не установлены, остановись до удаления: один Journal либо активный список недостаточен.

В одной строке подтверждения назови область/ID, затронутые привычки/ID и потерю связи каждой из них: «Удалить область X (ID) навсегда и снять её с A (ID), B (ID); привычки и остальные связи сохранятся — да?» Undo или восстановление прежнего Area ID не обещай.

После подтверждения, непосредственно перед `delete-area`, повторно дочитай **оба** списка `list-habits` с выбранным `areaId`: `archived=false` и `archived=true`, включая все страницы. Сравни полный набор `habitId` с подтверждённым составом. Если появился или исчез участник, останови запись и получи однострочное подтверждение изменённого набора потерь. Если полнота повторного чтения не установлена, остановись до удаления.

Затем получи свежие `get-habit` для всего актуального набора и сверь полные `areas[].id` и прочую конфигурацию с исходными данными. При изменившихся связях или существенных внешних изменениях останови запись, объясни изменение и получи однострочное подтверждение актуальных потерь. После нового подтверждения повтори эти предзаписные чтения. API не предоставляет атомарности или блокировки конкурентных правок: повторное чтение выявляет наблюдаемые изменения, но не исключает изменение между чтением и удалением.

После удаления проверь отсутствие области по правилам адресного `get-area`/полного списка, затем через `get-habit` подтверди сохранность **каждой** затронутой привычки и полный набор её остальных `areas[].id`. Общий 404 либо отсутствие в неполном списке не доказывает удаление. Недостаток Read-back после вызова — `unverified`; потерянные данные не восстанавливай и mutation не повторяй.

## В фоне

Только читай и собирай предложения для следующего разговора; не создавай, не назначай, не переименовывай и не удаляй области. Во внешнем уведомлении хоста сообщай количества без названий, если отдельного согласия на названия нет, по [setup.md](setup.md). Состояние группировки и состав используй в текущем разговоре, без ledger. ID выбранных ритуальных областей — разрешённая настройка памяти по setup.md; фоновый запуск её не меняет.
