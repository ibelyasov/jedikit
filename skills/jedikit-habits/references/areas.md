# Области Habitify

Область помогает видеть выбранные привычки вместе. Это отдельная группа Habitify, без дерева, наследуемых режимов или проектов SingularityApp. В просмотренных источниках прямая дополнительная польза Areas не установлена; это ограничение прочитанного корпуса, а не утверждение об отсутствии всех исследований. Не обещай ускоренное формирование, здоровье, снижение нагрузки или «баланс жизни» благодаря группе либо цвету. Возможное удобство фильтра оценивает пользователь.

Операции и согласие выполняй по [operation-policy.md](operation-policy.md), технический контракт — по [habitify-tools.md](habitify-tools.md). При сигналах риска примени [safety.md](safety.md): классификация не заменяет помощь человеку.

## Когда предложить

При setup/status или обзоре предложи один небольшой вариант, если наблюдается потребность: появилась вторая или следующая привычка сходного назначения, пользователь ищет связанные привычки или жалуется на длинный список. Назови конкретную пользу: «Эти две привычки удобно видеть вместе. Добавить их в выбранную область?» Число привычек — эвристика, а не обязательный порог.

Для одной привычки без запроса на группировку пропусти организацию. Не заполняй все сферы, не назначай квоты и не повторяй отклонённое предложение без новой потребности. Если вопрос только о времени дня, сначала рассматривай имеющийся Time of Day; это отдельный объект, не область и не напоминание.

Группировка существующих привычек не разрешает новые поведения, изменение планов или отметки. Сохраняй один эксперимент; на его обзоре меняй одну вещь. Область не заменяет конкретный сигнал действия, if–then или Safety-стоп.

## Выбрать область и название

1. Прочитай `list-areas` и явно выбранные привычки через `get-habit`. Проверь полноту списка и принадлежность объектов; при нескольких подходящих названиях задай один вопрос с рекомендуемым вариантом. Сначала предложи подходящую существующую область, затем при необходимости новую. Не создавай дубль и не назначай область скрыто по похожим названиям.
2. Для новой области согласуй `name`, учитывая известное предпочтение пользователя. Для чувствительного содержания предложи нейтральное имя вроде «Личное»; не добавляй диагноз или приватную интерпретацию без запроса. Названия областей видны в приложении, их отображение в уведомлениях неизвестно — скрытие не гарантируй. Не переименовывай существующие объекты сам.
3. Цвет `colorHex` и `icon` необязательны; не требуй их ради группировки. Для `create-area` обязателен `name`; для `update-area` меняй только согласованные поля. Точные типы, вложенность и аргументы бери из inputSchema хоста, а не из REST-примеров. После создания возьми `id` из ответа и прочитай `get-area`; после изменения сверь новые и сохранённые поля через `get-area`.

## Назначить или снять связь

Перед `update-habit` получи свежий `get-habit`. Установи полный текущий набор `areas[].id`, вычисли согласованный будущий набор с сохранением всех остальных назначений и передай **весь** `areaIds`: это замена набора, а не добавление одного ID. Для снятия выбранной связи исключи только её. Не отправляй `[]` или `null` для неоговорённого очищения.

Применяй guard **всей writable-конфигурации** из habitify-tools.md, сохраняя остальные поля привычки, цели, расписание, напоминания и `timeOfDayIds`. При неполных данных, неоднозначном преобразовании или необходимости догадки остановись до записи и предложи ручное изменение в приложении. После записи независимо прочитай `get-habit`, сравни полный набор `areas[].id` с ожидаемым и проверь сохранность прочей конфигурации; порядок ID не является изменением состава. Несовпадение либо недостаток данных означает `unverified`, без повтора или отката.

## Preview и выполнение

Для своего предложения покажи Preview и дождись подтверждения: точные области/`areaId`, выбранные привычки/`habitId`, старые → новые названия, полный старый → новый набор назначений, поля, последствия и порядок операций. Существенное изменение требует обновлённого Preview и нового согласия.

Явную одиночную команду с однозначным объектом выполняй сразу после исходного чтения, затем Read-back; не добавляй соседнюю группировку. При неоднозначности уточни один вопрос. Исключение — `delete-area`, всегда по правилам удаления ниже.

Создание области и назначение её привычке — группа операций: один Preview и одно подтверждение, затем `create-area` → `get-area` → `update-habit` с ID из ответа → `get-habit`. Все явно выбранные зависимые назначения включи в тот же Preview. Для неизменившейся группы повторных подтверждений скилла нет; кнопка допуска хоста остаётся отдельным слоем по operation-policy.md.

Проверь инструменты каждого этапа, включая Read-back, до первой записи. Выполняй запись → Read-back последовательно для каждого объекта. При первой ошибке, неизвестном исходе или несовпадении останови группу; адресно прочитай состояние без слепого повтора. Отчёт различает `applied` / `unverified` / `unapplied`, включая не начатые операции. Bulk, операции «на все привычки», автоматические повторы и откат запрещены.

Если исход `create-area` неизвестен и ID не получен, прочитай полный `list-areas` и найди согласованный `name` по разделу [«Неизвестный исход создания»](habitify-tools.md#неизвестный-исход-создания). Покажи найденные совпадения; совпадение или неполнота списка означают `unverified`. Не подставляй ID совпадения в зависимые назначения автоматически: группа остановлена, оставшиеся записи `unapplied`. Новое создание возможно только после явного решения пользователя. Отказ на кнопке хоста также останавливает группу; результат отклонённого вызова и оставшихся записей определи по operation-policy.md, не выполняй их повторно.

## Удалить область

`delete-area` доступен только по **явной просьбе пользователя**, после точного Preview и подтверждения после него, даже для одной буквальной команды. Агент не инициирует удаление: пустота, возраст или сходство названий его не разрешают. Подтверждённый Preview группы с перечисленными потерями достаточен без дополнительных подтверждений каждой операции.

До Preview прочитай выбранную область и **все страницы связанных активных и архивных привычек** через `list-habits` с `areaId`, отдельно `archived=false` и `archived=true`. Правила полноты — в habitify-tools.md. Получи адресные `get-habit` и сохрани полные наборы назначений затронутых привычек в текущем разговоре. Если фильтры, полнота или связи не установлены, остановись до удаления: один Journal либо активный список недостаточен.

Preview перечисляет область/ID, затронутые привычки/ID и потерю связи каждой из них. Область удаляется навсегда, привычки сохраняются вместе с прочими назначениями. Undo или восстановление прежнего Area ID не обещай.

После подтверждения, непосредственно перед `delete-area`, повторно дочитай **оба** списка `list-habits` с выбранным `areaId`: `archived=false` и `archived=true`, включая все страницы. Сравни полный набор `habitId` с подтверждённым Preview. Если появился или исчез участник, останови запись, обнови Preview и получи подтверждение изменённого набора. Если полнота повторного чтения не установлена, остановись до удаления.

Затем получи свежие `get-habit` для всего актуального набора и сверь полные `areas[].id` и прочую конфигурацию с исходными данными Preview. При изменившихся связях или существенных внешних изменениях останови запись и получи подтверждение обновлённого Preview. После нового подтверждения повтори эти предзаписные чтения. API не предоставляет атомарности или блокировки конкурентных правок: повторное чтение выявляет наблюдаемые изменения, но не исключает изменение между чтением и удалением.

После удаления проверь отсутствие области по правилам адресного `get-area`/полного списка, затем через `get-habit` подтверди сохранность **каждой** затронутой привычки и полный набор её остальных `areas[].id`. Общий 404 либо отсутствие в неполном списке не доказывает удаление. Недостаток Read-back после вызова — `unverified`; потерянные данные не восстанавливай и mutation не повторяй.

## В фоне

Только читай и собирай предложения для следующего разговора; не создавай, не назначай, не переименовывай и не удаляй области. Во внешнем уведомлении хоста сообщай количества без названий, если отдельного согласия на названия нет, по [setup.md](setup.md). ID областей и состояние группировки используй в текущем разговоре, не сохраняй их в native memory или отдельном ledger; settings-only правила setup.md остаются без расширения.

Для сопровождающих: основания, факты vendor и ограничения исследований — [research/habits/areas.md](https://github.com/ibelyasov/jedikit/blob/main/research/habits/areas.md), доступ 2026-10-06. Выполнение host tools, API ↔ app consistency и полнота Read-back здесь не подтверждены.
