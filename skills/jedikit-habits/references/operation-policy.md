# Записи и подтверждения

Применяй эти правила к Habitify, настройкам встроенной памяти хоста и планировщика хоста.

## Выбери правило

| Запрос | Действие |
| --- | --- |
| Чтение конкретной привычки или приглашение без записи | Выполни без подтверждения в пределах запроса |
| `urge` без отдельной команды записи | Только разговорная поддержка; не разрешает отметку, заметку, уведомление или сообщение другому человеку |
| Явная одиночная команда с однозначной целью, датой и значением | Выполни сразу, затем Read-back; не требуй повторного согласия |
| Изменение, предложенное агентом | Покажи точный preview, дождись подтверждения, выполни и прочитай обратно |
| Две и более записи | Покажи один preview всей группы операций; одно подтверждение; последовательно запись → Read-back; стоп на первой ошибке |

Не считай общее пожелание вроде «хочу наладить питание» разрешением создать привычку. При неоднозначности любого запроса задай ровно один вопрос и предложи рекомендуемую трактовку; зависимую запись отложи до ответа. Не добавляй соседние записи к явной одиночной команде.

## Составь preview

Укажи выбранную привычку и `habitId`, операции в порядке выполнения, конкретные поля и новые значения, прежние значения для изменения, даты и timezone, текст плана или заметки. Для создания назови новую привычку и зависимые записи с ID из ответа создания. Назови последствия отмены, архива или замены существующих значений. Ключ и полный заголовок авторизации не показывай.

После изменения существенных параметров preview получи подтверждение обновлённого списка. Подтверждение не распространяется на будущие операции. Не запрашивай подтверждение второй раз для неизменившейся группы.

## Выполни и прочитай обратно

1. Прочитай исходные значения выбранного объекта. Для Habitify используй [rest-api.md](rest-api.md) без расширения до аккаунта; для настроек памяти или расписания — встроенные возможности соответствующего хоста.
2. Выполняй по одной операции через её источник. Не используй batch, параллельные записи или автоматические retries.
3. После каждой успешной записи независимо прочитай результат из того же источника: Habitify — GET по rest-api.md; память — фактические сохранённые настройки; планировщик — фактическую конфигурацию созданного или изменённого расписания. Сравни поля с ожидаемым результатом. Ответ инструмента записи сам по себе не является Read-back. Если хост не даёт отдельного чтения, назови ограничение; не подменяй его файлом или записью в Habitify и не объявляй результат подтверждённым.
4. При первой ошибке записи или Read-back останови группу. После timeout или обрыва соединения сначала прочитай результат; не повторяй запись вслепую.
5. В отчёте перечисли «применено / результат не подтверждён / не применено» (`applied` / `unverified` / `unapplied`), ошибку и возможный следующий шаг. Не считай отсутствие данных доказательством успеха или отсутствия записи.

Не откатывай автоматически. Отмена — отдельная запись по тому же правилу явной команды или предложения. Для отмены отметки соблюдай область действия из rest-api.md; отмена всех отметок одной привычки за дату не равна отмене последней отметки.

На запуске от планировщика хоста ничего не записывай, включая настройки памяти и исправления данных. Собери предложения для следующего разговора; не исполняй их по прежнему общему согласию на расписание.
