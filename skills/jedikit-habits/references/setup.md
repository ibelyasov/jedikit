# Setup, status, память и расписание

Записи в Habitify, `memory` и `cronjob_manage` — по [write-policy.md](write-policy.md).

## Setup

1. Используй известные timezone и окно обзора; недостающее для текущего действия собери одним `clarify`. Окно обзора не нужно для простой Отметки или чтения списка.
2. Проверь инструменты серверов `habitify_read` и `habitify` для сценария, включая Read-back, по [tools.md](tools.md#серверы-и-discovery). Покажи существующие привычки ([поиск](tools.md#поиск-привычки-по-названию)).
3. Если привычка и действие уже названы, найди её и выполни запрос без повторного выбора. Открытый setup без выбранного действия — предложи один подходящий ход одной строкой и выполни по «Да»; набор изменений — один Preview. Новую привычку веди по [experiments.md](experiments.md).
4. После выбора прочитай детали привычки и выбери заметку плана по [experiments.md](experiments.md#заметка-плана).
5. Ритм обзоров — [review.md](review.md#дата-следующего-обзора); известное окно не спрашивай повторно.
6. Хочет расписание — заведи задание `cronjob_manage` по [разделу ниже](#расписание).

Потребность в группировке — [areas.md](areas.md#когда-предложить). Запрос Ритуала — [rituals.md](rituals.md); анкету о Ритуалах без запроса не проводи.

## Названия

Не пытайся отличить владельца от участника публичного onboarding. Для нового названия используй явно заданное имя или известное предпочтение; если без выбора не обойтись, спроси о точном или нейтральном имени вместе с остальными блокирующими пробелами. Объясни, что названия видны в Habitify и его напоминаниях. Чувствительное название по собственной догадке не создавай; в сексуальной теме — [sexual-behavior.md](sexual-behavior.md#возраст). Предпочтение сохраняй как настройку памяти.

## Память

Храни только настройки, распознавая их из обычной фразы без специальной команды:

- timezone, ритм и окна обзоров, предпочтение названий;
- выбранный `habitId` эксперимента (необязательно);
- `areaId` Областей, выбранных пользователем как Ритуалы, и для каждой — `habitId` первой привычки, если пользователь её назвал ([rituals.md](rituals.md#ритуал-в-настройках)).

Не храни: все ID из списка привычек, состав и порядок остальных привычек Ритуала, План эксперимента, даты следующего и проведённого обзора, состояния «активный / Поддержание / пауза», Отметки, Тягу, вес, причины срыва, секреты.

Запись настройки — по write-policy.md и разделу ниже. Если `memory` недоступен, один раз за сессию сообщи ограничение и продолжай с данными разговора; состояние обзоров из старых записей не восстанавливай.

### Где хранить настройки

- Только инструмент `memory` с `target="memory"`: одна компактная запись этого скилла, начинающаяся с `JediKit habits:`. Отдельного чтения нет: текущие записи видны в контексте памяти.
- Записи с этим префиксом нет — `action="add"`, `content`. Есть — `action="replace"`, `old_text` (уникальный фрагмент этой записи) и `content` с полной новой записью: replace заменяет запись целиком, поэтому перенеси в неё все сохраняемые значения. Вторую запись не создавай, `target="user"` не используй.
- `done: true` — запись применена; это Read-back настроек. `staged: true` с `pending_id` — запись ждёт одобрения: скажи «Сохранение ждёт подтверждения памяти: `/memory pending`» и не называй настройку сохранённой. Отказ, например по лимиту, — `unapplied`; ответ без `done` и `staged` — `unverified`.
- Лимит около 2 200 символов на все записи памяти профиля: храни только выбранные значения и ID, остальное перечитывай у провайдера. При отказе по лимиту сообщи об этом; чужие записи не сокращай.
- Файлы скиллов JediKit (`SKILL.md`, `references/`, `tools.json`) только для чтения: не вызывай `skill_manage`, не создавай файлов настроек и не обходи `memory` другим способом, даже если подсказка Hermes советует хранить предпочтения в скилле.
- Если `memory` недоступен, настройки действуют только в текущем разговоре; сохранение не обещай.

## Status

- Эксперимент: найди привычку, прочитай детали и адресную статистику за запрошенный период (по умолчанию — текущая дата по [tools.md](tools.md#даты-и-единицы)). Покажи наблюдаемое поведение, доступные Отметки, дату обзора из доступного плана и ограничения данных. План нужен для разбора и даты обзора; простое чтение Отметок выбором заметки не задерживай.
- «Какие привычки сегодня?» или конкретный день — [Обзор дня](tools.md#обзор-дня), без записи Отметок.
- Ритуал — [rituals.md](rituals.md#статус).

Отделяй слова пользователя от прочитанного в Habitify. Соблюдение плана или факт обзора из пропущенных данных не выводи. Status только читает.

## Расписание

Задание создавай только по явной просьбе или после «Да» на предложение, по [write-policy.md](write-policy.md#кто-разрешает-запись): `cronjob_manage(action="create", schedule=…, prompt=…, skills=[…])`.

- `schedule` — cron-выражение или интервал вида `every 2h`. Поля timezone нет: время считается в timezone профиля Hermes; если пояс из настроек может отличаться, скажи это в предложении.
- `skills` — имя этого скилла так, как оно загружено (голое `jedikit-habits` или с префиксом `agent-plugin-…:`). `deliver` не задавай, кроме места, явно названного пользователем; по умолчанию доставка идёт в чат, где создано задание. `enabled_toolsets` не задавай.
- Read-back — `cronjob_manage(action="list")`: найди задание по ID и сверь расписание, текст, скиллы и доставку. Список подтверждает только задание, не запуск и не доставку.
- Фоновому запуску нужно чтение `habitify_read` (toolset `mcp-habitify_read`) в toolsets cron Hermes. Если инструментов нет, запуск называет недостающее и показывает только доступное, без обхода.

Текст задания (`prompt`) начинай маркером `[расписание jedikit]`; такой запуск только читает ([write-policy.md](write-policy.md#фоновый-запуск)), `clarify` в cron нет. В задании укажи выбранные ID и приглашение к обзору, если наступила дата из доступного плана; без плана — согласованное приглашение по окну без утверждения о просрочке. Пропущенный обзор не отслеживай и ledger в памяти не создавай.

Во внешнем уведомлении сообщай только количества, например «Есть 1 эксперимент для обзора». Названия — только при отдельном согласии на этот канал. Заметки, Тягу, срывы и другие чувствительные подробности не включай.
