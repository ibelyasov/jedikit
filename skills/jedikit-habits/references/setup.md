# Setup и status

Операции выполняй по [operation-policy.md](operation-policy.md).

## Setup

1. Используй известные timezone и окно обзора. Запрашивай только недостающее, необходимое для текущего действия; все блокирующие пробелы собери одним сообщением. Окно обзора не нужно для простой отметки или чтения списка.
2. Не пытайся отличить владельца от участника публичного onboarding. При создании названия используй явно заданное имя или известное предпочтение; если без выбора не обойтись, спроси о точном или нейтральном имени вместе с остальными блокирующими пробелами. Объясни, что названия видны в Habitify и его напоминаниях. Сохраняй предпочтение только как настройку встроенной памяти хоста по разделу ниже и operation-policy.md. Не создавай чувствительное название по собственной догадке; возрастную границу для сексуального поведения бери из [sexual-behavior.md](sexual-behavior.md).
3. Проверь доступные инструменты хоста серверов `habitify_read` (чтение) и `habitify` (запись) и их inputSchema по [habitify-tools.md](habitify-tools.md); для сценария нужны и инструменты Read-back. Покажи существующие привычки по разделу «Поиск привычки по названию». Если пользователь уже назвал привычку и действие, найди её и выполни запрос по operation-policy.md без повторного выбора. При открытом setup без выбранного действия предложи один подходящий ход одной строкой и выполни по «да»; набор изменений требует одного Preview. Намерение создать новую веди по [experiments.md](experiments.md).
4. После выбора прочитай детали привычки по habitify-tools.md, а заметку плана выбери по разделу «Выбор и запись заметки плана» [experiments.md](experiments.md). При недоступном инструменте назови отсутствующие base names из [tools.json](../tools.json), включая нужный Read-back, и предложи владельцу проверить на хосте подключение сервера, указанного у каждой отсутствующей операции в tools.json: `habitify_read` для чтения, `habitify` для записи. Останови зависимый сценарий; не проверяй secret-окружение, не запрашивай ключ в чате и не меняй аккаунт или подключение.
5. Для настройки обзора используй ритм из [review.md](review.md) и уже известное окно; не спрашивай его повторно.
6. Если пользователь хочет расписание, настрой планировщик хоста на приглашение или проверку выбранных ID по сценарию ниже.

При наблюдаемой потребности — второй сходной привычке, поиске связанных привычек или жалобе на длинный список — прочитай [areas.md](areas.md) и предложи один небольшой вариант группировки, сначала в существующую область. Для одной привычки без запроса лишняя организация не нужна; отклонённое предложение без новой потребности не повторяй. Запрос ритуала веди по [rituals.md](rituals.md); сон ритуалом не считай.

Настройку «какие Области — ритуалы» распознавай из обычной фразы, например «Область Утро — мой ритуал». Найди выбранную область по имени или ID через `list-areas`/`get-area`, сохрани её `areaId` как настройку ритуала и прочитай настройку обратно по operation-policy.md. Явный однозначный выбор выполняй без повторного согласия; неоднозначность уточни вместе с другими блокирующими пробелами. Не проводи анкету о ритуалах без запроса.

## Встроенная память хоста

Используй встроенную память хоста без предположений о tool-call syntax. Сохраняй только настройки: timezone, ритм и окна обзоров, предпочтение названий, ID областей, выбранных пользователем как ритуалы; выбранный `habitId` — необязательная настройка. Не сохраняй все ID из списка привычек, состав и порядок ритуала. Распознавай запрос настройки из обычной фразы пользователя без специальной команды. Не создавай собственную схему хранилища или файловый fallback. Запись настройки и её Read-back выполняй по operation-policy.md.

Не записывай в память план эксперимента, дату следующего обзора, дату завершённого обзора, состояния «активный / поддержание / пауза», отметки, тягу, вес, причины срыва или секреты. Выбор и перезапись заметки плана заданы experiments.md, техническое чтение и Read-back — habitify-tools.md.

Если память недоступна, один раз за сессию сообщи ограничение и продолжай с данными текущего разговора. Не обещай сохранение между сессиями и не восстанавливай состояние обзоров из старых записей памяти.

## Status

Для выбранного эксперимента найди привычку по разделу «Поиск привычки по названию» в habitify-tools.md, прочитай её детали и адресную статистику за запрошенный период. План по experiments.md нужен для разбора эксперимента и даты обзора; простое чтение отметок не задерживай выбором заметки. Если период не задан, используй текущую дату по правилам habitify-tools.md. Покажи наблюдаемое поведение, доступные отметки, дату обзора из доступного плана и ограничения данных. Статус и обзор ритуала — по rituals.md.

Для запроса «Какие привычки сегодня?» или обзора конкретного дня используй раздел «Обзор дня» в habitify-tools.md. Покажи данные запрошенной даты без записи отметок. Отделяй слова пользователя от прочитанного в Habitify.

Не выводи соблюдение плана или факт завершения обзора по пропущенным данным. Status — чтение доступных данных.

Если пользователь ищет несколько связанных привычек или жалуется на длинный список, используй [areas.md](areas.md) для одного полезного предложения. Предложение не разрешает запись или новые эксперименты. Если вопрос только о времени дня, сначала рассматривай существующий Time of Day.

## Запуск от планировщика хоста

При настройке задания начинай его текст с маркера `[расписание jedikit]`. Распознавание такого запуска и его ограничения заданы в разделе «Распознай запуск по расписанию» [operation-policy.md](operation-policy.md).

В задании укажи выбранные ID и приглашение к обзору, если дата из доступного плана наступила; если план недоступен, используй согласованное приглашение по окну без утверждения о просрочке. Не отслеживай пропущенный обзор и не создавай ledger в памяти.

Во внешнем уведомлении сообщай только количества: например, «Есть 1 эксперимент для обзора». Названия добавляй лишь при отдельном согласии на этот канал. Не включай заметки, тягу, срывы или иные чувствительные подробности.
