# Setup и status

Операции выполняй по [operation-policy.md](operation-policy.md).

## Setup

1. Уточни timezone и удобное окно обзора. Используй уже известные настройки.
2. Для владельца сохрани точные названия. В публичном onboarding спроси, предпочитает ли человек точное или нейтральное название; объясни, что название будет видно в Habitify. Не создавай чувствительное название по собственной догадке.
3. Покажи существующие привычки по разделу «Поиск привычки по названию» в [rest-api.md](rest-api.md). Если пользователь уже назвал привычку, найди её по тому же алгоритму. Предложи: «Использовать эту привычку, изменить её план или оставить как есть?» Намерение создать новую веди по [experiments.md](experiments.md).
4. После выбора прочитай детали привычки и доступный план по rest-api.md. При отсутствии доступа назови ограничение и предложи владельцу проверить REST-доступ и secret-окружение хоста. Не запрашивай ключ в чате и не меняй аккаунт или подключение.
5. Согласуй окно обзора, используя ритм из [review.md](review.md).
6. Если пользователь хочет расписание, настрой планировщик хоста на приглашение или проверку выбранных ID по сценарию ниже.

## Встроенная память хоста

Используй встроенную память хоста без предположений о tool-call syntax. Сохраняй только настройки: timezone, ритм и окна обзоров, предпочтение названий; выбранный `habitId` — необязательная настройка. Не сохраняй все ID из списка привычек. Распознавай запрос настройки из обычной фразы пользователя без специальной команды. Не создавай собственную схему хранилища или файловый fallback.

Не записывай в память план эксперимента, дату следующего обзора, дату завершённого обзора, состояния «активный / поддержание / пауза», отметки, тягу, вес, причины срыва или секреты. Способ хранения и чтения плана задан rest-api.md.

Если память недоступна, один раз за сессию сообщи ограничение и продолжай с данными текущего разговора. Не обещай сохранение между сессиями и не восстанавливай состояние обзоров из старых записей памяти.

## Status

Для выбранного эксперимента найди привычку по разделу «Поиск привычки по названию» в rest-api.md, прочитай её детали, доступный план и адресную статистику за запрошенный период. Если период не задан, используй текущую дату по правилам rest-api.md. Покажи наблюдаемое поведение, доступные отметки, дату обзора из плана и ограничения данных.

Для запроса «Какие привычки сегодня?» или обзора конкретного дня используй раздел «Обзор дня» в rest-api.md. Покажи данные запрошенной даты без записи отметок. Отделяй слова пользователя от прочитанного в Habitify.

Не выводи соблюдение плана или факт завершения обзора по пропущенным данным. Status — чтение доступных данных.

## Запуск от планировщика хоста

Читай только выбранные ID и доступные планы. Пригласи к обзору, если дата из плана наступила; если план недоступен, отправь согласованное приглашение по окну без утверждения о просрочке. Не отслеживай пропущенный обзор и не создавай ledger в памяти.

Во внешнем уведомлении сообщай только количества: например, «Есть 1 эксперимент для обзора». Названия добавляй лишь при отдельном согласии на этот канал. Не включай заметки, тягу, срывы или иные чувствительные подробности.
