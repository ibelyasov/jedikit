# Словарь JediKit

## Что куда относится

| Термин | Человеческое объяснение |
| --- | --- |
| Событие | Обязательство в календаре со временем: встреча, приём, договорённость. Намерение без договорённости — задача. |
| Бронь | Время в календаре под задачу. Это ссылка, а не копия: срок, состояние и выполнение остаются в SingularityApp. Прошедшая Бронь ничего не закрывает. |
| Распорядок | Роль события в календаре: регулярный блок поведения с устойчивым временем и длительностью, например Ритуал целиком или сон. Ставится только по просьбе пользователя. |
| Ритуал | Группа привычек, выполняемых подряд в определённое время дня. В Habitify это Область, отмеченная в настройках как Ритуал. Сон — одно действие, а не Ритуал. |
| План дня | Фокус-лист, разложенный по окнам календаря с проверкой вместимости и Бронями. |
| Свободное окно | Промежуток без Событий, Броней и Распорядка внутри границ дня из настроек. |
| Фокус-лист | Выбранные на сегодня задачи без проверки календаря и вместимости. Эту проверку делает План дня. |

В календаре видно то, что занимает определённый промежуток в определённый момент: Событие, Бронь или Распорядок. Отдельные привычки внутри Ритуала и привычки без устойчивого времени туда не попадают. «Плавание с тренером во вторник в 19:00» — Событие по договорённости; привычка плавать остаётся в Habitify.

## Задачи — SingularityApp

| Термин | Человеческое объяснение |
| --- | --- |
| Область | Проект верхнего уровня, задающий контекст жизни: Работа, Личное или выбранный пользователем. |
| Папка | Проект с дочерними проектами. Может содержать одиночные задачи; собственного результата и следующего шага не требует. |
| Проект | Проект без дочерних проектов: многошаговое дело с результатом и стартуемым Следующим шагом. |
| Режим поддерева | Наследуемый признак Области или Папки: рабочие дни, личные дни, всегда или когда-нибудь. Это не Распорядок календаря. |
| Когда-нибудь | Режим поддерева: проекты не попадают в Daily open, не требуют Следующего шага и пересматриваются ежемесячно. |
| Задача | Одно физическое действие: глагол, объект и видимый признак готовности. |
| Следующий шаг | Задача проекта, которую можно начать сейчас; обычно одна, две — если независимы и параллельны. |
| Раздел | Блок задач внутри проекта, когда у длинного проекта видны реальные части. |
| Тег | Пользовательский признак для повторяющегося вопроса выбора между задачами разных проектов. |
| Чек-лист | Список-памятка внутри одной задачи, а не план шагов. |
| Inbox item | Сырая, ещё не разобранная запись во входящих. |
| Capture | Немедленная запись исходной мысли во Inbox без классификации. |
| Triage | Разбор одного Inbox item: тип, чистовая формулировка, место в дереве. |
| Идея / Справка / Встреча | Inbox item, который пользователь переносит в собственное место; датированная договорённость может стать Событием. |
| Срок | Внешний жёсткий срок (`deadline`), после которого наступают последствия. |
| Плановая дата | Выбранная пользователем дата начала задачи (`start`), а не Срок. |

## Обзоры

| Термин | Человеческое объяснение |
| --- | --- |
| Ресурс дня | Самооценка низкий / обычный / высокий для размера Фокус-листа, а не измерение. |
| Daily open | Утренний обзор: вчерашние хвосты, Ресурс дня, Фокус-лист. Затем при необходимости — План дня. |
| Daily close | Вечерний обзор: остатки дня, затронутые проекты, Гвоздодёр. |
| Гвоздодёр | Обратная прокрутка прошедшего дня для незаписанных обязательств. |
| Weekly | Еженедельный обзор Inbox, всех проектов, следующих шагов и структуры. |
| Inbox debt | Накопившиеся неразобранные Inbox items для отдельных сессий по 15, 10 или 5 минут. |

## Поведение — Habitify

| Термин | Человеческое объяснение |
| --- | --- |
| Область Habitify | Группа привычек; отличается от Области в SingularityApp. Может быть отмечена как Ритуал. |
| Эксперимент | Проверка одной гипотезы об одном наблюдаемом поведении, привязанная к привычке. |
| План эксперимента | Текст в заметке привычки: цель, поведение, триггер, минимальное действие или замена, if–then, дата обзора, stop-rule. |
| Отметка | Запись о выполнении, срыве, пропуске или количестве за дату. |
| Тяга | Момент сильного желания сорваться; скилл предлагает действия из плана. Это не диагноз. |
| Обзор эксперимента | Разбор по плану: оставить, изменить одну вещь, пауза или завершить. |
| Поддержание | Состояние эксперимента, ставшего привычным; обзор раз в месяц. |
| Stop-rule | Заранее оговорённое условие остановки эксперимента. |
| Safety-стоп | Остановка коучинга при признаках клинического риска с направлением к специалисту. |
| Время старта Ритуала | Напоминание первой привычки. Порядок привычек задаётся ручной сортировкой в приложении; длительности в Habitify нет. |

## Операции и хост

Эти определения объясняют слова в отчётах; разрешения и точные правила берутся только у скилла-владельца операции.

| Термин | Человеческое объяснение |
| --- | --- |
| Preview | Точный набор изменений, собранный агентом, перед подтверждением. Для одиночного предложения достаточно одной строки и «да». |
| Группа операций | Две и более записи последовательно, со стопом на первой ошибке. Явно названные пользователем — сразу; собранные агентом — после одного Preview. |
| Read-back | Чтение записанного обратно из провайдера через инструмент хоста. Ответ на запись сам по себе его не заменяет. |
| Инструменты хоста | Предоставленные агенту операции провайдера; подключения и транспорт принадлежат хосту. |
| Контракт инструментов | Декларативный `tools.json` провайдерного скилла: ожидаемые серверы, имена операций и доступ. Это не настройка подключения. |
| Адаптер хоста | Доверенный компонент, предоставляющий операции Habitify по REST/OpenAPI v2; ключ остаётся у адаптера. |
| Native memory | Встроенная память хоста только для настроек; не источник состояния задач, отметок или проведённых обзоров. |
