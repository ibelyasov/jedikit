### Чтение, время и поля

- `list-events.calendarId` принимает строку либо массив до 50 ID/имён. Для однозначной адресации используются выбранные ID. Схема не публикует `pageToken`, `singleEvents` или `showDeleted`: нельзя передавать их по аналогии с REST или объявлять полноту ответа доказанной только по inventory.
- Без `fields` сервер не ставит field mask, и событие возвращается полным. С `fields` к запрошенным полям добавляется default-набор **`id,summary,start,end,status,htmlLink,location,attendees,reminders,recurrence`**. `description`, `recurringEventId`, `originalStartTime`, `transparency`, `extendedProperties` и `colorId` в default-набор не входят и называются в `fields` явно; `colorId` есть в allowlist field mask закреплённого source, `eventLabelId` — нет ([EC-G-17](../sources.md)). Метка Брони/Распорядка хранится в `description`; отсутствие незапрошенного поля не означает отсутствие метки.
- Для обзоров задаются явные `timeMin,timeMax` как ISO 8601 без смещения и IANA `timeZone`; обязательность границ в сценарии строже required схемы, где обязателен только `calendarId`. `get-current-time(timeZone)` задаёт дату для «сегодня» и относительных дат.
- Timed `start/end` — `YYYY-MM-DDTHH:MM:SS` + IANA `timeZone`; all-day — `YYYY-MM-DD`, `end` exclusive. Схема допускает строковое JSON-представление per-field zone; при embedded offset он приоритетнее `timeZone`. JediKit использует согласованный домашний пояс и не подменяет входы REST-полями `startTime/endTime`.

Источник: переданные схемы [GCAL-NSPADY-TOOLS-2.7.0](../sources.md), 2026-10-08. Живая проверка [GCAL-CLANWRIGHT-LIVE-2026-10-08](../sources.md): `list-events` по массиву из двух календарей возвращает `events`, `totalCount`, `calendars`, у события есть `calendarId`; вхождения серии приходят отдельными записями с собственным `id` вида `<серия>_<UTC>`, `recurringEventId` и `originalStartTime`; Read-back через `get-event` возвращает `description`. На хосте понадобилось `NODE_USE_ENV_PROXY=1`: пакетный запрос по нескольким календарям идёт через Node `fetch()`.

### Серии, дубли и конфликты

`recurrence` — массив RFC 5545, например `RRULE:…`. У `update-event.modificationScope` три режима: `thisEventOnly` с `originalStartTime`, `thisAndFollowing` с `futureStartDate`, `all`. Эти вспомогательные поля условно нужны для соответствующего сценария; они не входят в top-level required схемы. `thisAndFollowing` может затрагивать несколько записей реализации и не объявляется транзакцией. [GCAL-NSPADY-TOOLS-2.7.0](../sources.md), [GCAL-CLANWRIGHT-2026-10-08](../sources.md).

`delete-event` не принимает область серии: ID экземпляра адресует вхождение, ID родителя — серию. Для «это и следующие» принятый сценарий использует `update-event` родителя с окончанием `RRULE` (`UNTIL`) перед выбранным вхождением. Нельзя отправить несуществующий delete scope или выдуманный ID. Если чтение не дало ID экземпляра, удаление одного вхождения не подтверждено доступными данными; предлагается поддержанный режим изменения либо действие в интерфейсе. Адресация Google описана в [Recurring events](https://developers.google.com/workspace/calendar/api/guides/recurringevents), доступ 2026-10-08; schema/ограничение выбранного транспорта — [GCAL-NSPADY-TOOLS-2.7.0](../sources.md). Вживую ([GCAL-CLANWRIGHT-LIVE-2026-10-08](../sources.md)) `delete-event` по ID экземпляра удаляет одно вхождение, по ID серии — всю серию с исключениями. `thisEventOnly` работает только с `originalStartTime` со смещением: naive-время сервер трактует как UTC при построении ID экземпляра и отвечает `Not Found`. `thisAndFollowing` делит серию, но новая часть получает исходное `RRULE` с `COUNT` без пересчёта (было 5 вхождений, стало 3 + 5). Вывод, вживую не проверенный: правило новой части передаётся явно (предпочтительно `UNTIL`), а Read-back сверяет его. `all` по ID старой части меняет её вхождения, включая исключения, и не трогает новую часть.

`create-event.allowDuplicates` по описанию схемы default `false`: почти точные дубли с similarity **≥0.95** блокируются. Отдельный `duplicateSimilarityThreshold` описан с default **0.7** для потенциальных дублей; это не тот же порог. При отказе скилл показывает найденное событие и создаёт с `allowDuplicates:true` только после «создай всё равно». Проверка сходства не заменяет устойчивую адресацию и не гарантирует идемпотентность. [GCAL-NSPADY-TOOLS-2.7.0](../sources.md).

`calendarsToCheck` задаёт календари проверки конфликтов, default — только календарь записи. У `update-event.checkConflicts` описан default true при смене времени. Вживую ([GCAL-CLANWRIGHT-LIVE-2026-10-08](../sources.md)) конфликт только предупреждает: create и update выполняются, ответ содержит `event`, `conflicts` (событие, календарь, длительность и доля пересечения) и `warnings` при `isError: false`. Точный дубль блокируется ошибкой `Duplicate event detected (95% similar)… set allowDuplicates to true`; похожее событие (0.7) создаётся с `duplicates` и `warnings`. Скилл считает пересечения сам до записи и не переносит другие события автоматически. Дубли и временные пересечения — разные результаты. [GCAL-NSPADY-TOOLS-2.7.0](../sources.md), [GCAL-CLANWRIGHT-2026-10-08](../sources.md).

## Официальный Google Calendar MCP

Этот раздел сохраняет сравнительное чтение 2026-10-07. Официальный remote MCP не выбран для текущего контракта JediKit; его имена с `_`, поля и ограничения не переносятся на nspady с именами через `-`.

**DOC:** официальный remote MCP существует: `https://calendarmcp.googleapis.com/mcp/v1`, **Developer Preview**, OAuth 2.0, Streamable HTTP. Требуются участие в Google Workspace Developer Preview Program и Cloud project. Программа указывает Workspace account и проверку/регистрацию проекта; consumer Gmail eligibility прямо не подтверждена. Pre-GA features нельзя включать в публичные applications до GA. Это ограничение использования именно preview-сервиса; оно не характеризует выбранный OSS MCP. Это отдельный Google сервис, а не встроенный Hermes toolset. [Google setup](https://developers.google.com/workspace/guides/configure-mcp-servers), [MCP reference](https://developers.google.com/workspace/calendar/api/v3/reference/mcp), [Preview Program](https://developers.google.com/workspace/preview), [GC-MCP-SETUP](../sources.md), [GC-MCP-REF](../sources.md), [GC-MCP-PREVIEW](../sources.md).

Существенные отличия от REST:

- `calendarId` по умолчанию primary; для сквозного обзора нужно перечислять календари и читать каждый. `list_events` поддерживает pagination (default 100, max 250), но его default event types исключают `WORKING_LOCATION` и `BIRTHDAY`. Параметр REST `singleEvents` не опубликован. Полноту раскрытия серий нельзя приписать MCP по REST-контракту. [list reference](https://developers.google.com/workspace/calendar/api/v3/reference/mcp/tools_list/list_events), [GC-MCP-LIST](../sources.md).
- `create_event` принимает `recurrenceData`; в input `update_event` нет изменения recurrence, scope «one/series/following», `extendedProperties`, `source`, `etag/If-Match` или custom event ID. У create также нет этих metadata/concurrency полей. Нельзя обещать их по факту наличия REST API. [create](https://developers.google.com/workspace/calendar/api/v3/reference/mcp/tools_list/create_event), [update](https://developers.google.com/workspace/calendar/api/v3/reference/mcp/tools_list/update_event), [GC-MCP-CREATE](../sources.md), [GC-MCP-UPDATE](../sources.md).
- MCP использует `availability=AVAILABILITY_BUSY|AVAILABILITY_FREE`; REST — `transparency=opaque|transparent`. MCP `notificationLevel` default — `ALL`; не оставлять этот side effect неявным. MCP `timeZone` overrides offsets в start/end, поэтому нельзя автоматически переносить правила REST. [create](https://developers.google.com/workspace/calendar/api/v3/reference/mcp/tools_list/create_event), [GC-MCP-CREATE](../sources.md).
- Setup перечисляет только `calendar.calendarlist.readonly, calendar.events.freebusy, calendar.events.readonly`. Страницы write tools требуют `calendar.events` или `calendar`: **расхождение общей инструкции и method reference**, а не доказательство writes с read-only grant. Разделение endpoint на read/write не опубликовано; его должен обеспечить хост фильтрами и правами. [setup](https://developers.google.com/workspace/guides/configure-mcp-servers), [update scopes](https://developers.google.com/workspace/calendar/api/v3/reference/mcp/tools_list/update_event#authorization-scopes), [GC-MCP-SETUP](../sources.md), [GC-MCP-UPDATE](../sources.md).

## Google Calendar API v3: бизнес-контракт

Ниже **DOC**, отдельно от MCP. База REST — `https://www.googleapis.com/calendar/v3`. Реальная реализация хоста должна документировать покрытие этих возможностей.

### Календари, список и доступ

`Calendars` — сам календарь; `CalendarList` — запись существующего календаря в списке пользователя с его цветами/default reminders. Создание secondary calendar и подписка на существующий — разные операции, как удаление календаря и удаление из списка. Primary calendar нельзя удалить. ACL и присутствие в CalendarList независимы; sharing не гарантирует появления в списке. [Concepts](https://developers.google.com/workspace/calendar/api/concepts/events-calendars#calendar_and_calendar_list), [sharing](https://developers.google.com/workspace/calendar/api/concepts/sharing), [GC-API-01](../sources.md), [GC-API-04](../sources.md).

Права различают `freeBusyReader, reader, writerWithoutPrivateAccess, writer, owner`; `owner` как manager role не равен единственному `dataOwner`. `private` не скрывает детали от обычного `writer`. Доменная политика может ограничивать sharing. **PROJECT:** скиллу достаточно чтения списка и событий; создание/удаление календарей и изменение ACL не следуют из нужных сценариев. [ACL](https://developers.google.com/workspace/calendar/api/v3/reference/acl), [CalendarList](https://developers.google.com/workspace/calendar/api/v3/reference/calendarList), [GC-API-05](../sources.md), [GC-API-02](../sources.md).

### День/неделя, время и серии

Для дня/недели `events.list(singleEvents=true, orderBy=startTime)` раскрывает instances вместо parent. `timeMin` — exclusive lower bound **по end**, `timeMax` — exclusive upper bound **по start**: событие, начавшееся раньше дня и продолжающееся в нём, не должно теряться. RFC3339 bounds требуют offset. Pagination default 250/max 2500; даже пустая page не завершает обход, если есть `nextPageToken`. [list](https://developers.google.com/workspace/calendar/api/v3/reference/events/list#parameters), [GC-API-07](../sources.md).

All-day использует `start.date/end.date`, timed — `dateTime`; end exclusive. Для 7 октября all-day: `2026-10-07 → 2026-10-08`. Timed требует offset либо явного IANA `timeZone`; recurring events требуют timezone раскрытия. Timezone календаря влияет на фильтрацию all-day. **O:** хранить IANA zone для повторений по локальным часам, явно показывать zone в Preview; конкретное разрешение DST ambiguity не исследовано. [Concepts](https://developers.google.com/workspace/calendar/api/concepts/events-calendars), [insert](https://developers.google.com/workspace/calendar/api/v3/reference/events/insert#request-body), [GC-API-01](../sources.md), [GC-API-09](../sources.md).

`recurrence` содержит RRULE/RDATE/EXDATE (reference также EXRULE), без DTSTART/DTEND. Parent series, occurrence и изменённое исключение — разные объекты. Для одного occurrence читать instances и менять его ID. `recurringEventId` связывает с parent, `originalStartTime` идентифицирует occurrence даже после переноса. Cancel instance можно изменением `status=cancelled`. Массовые instance edits для всей серии создают лишние исключения и уведомления. [Recurring guide](https://developers.google.com/workspace/calendar/api/guides/recurringevents#access_instances), [instances](https://developers.google.com/workspace/calendar/api/v3/reference/events/instances), [GC-API-13](../sources.md), [GC-API-12](../sources.md).

**Граница чтения 2026-10-07:** официальный поисковый индекс описывал «this and following» как trim старой series через UNTIL/COUNT + insert новой, со сбросом будущих exceptions; в прочитанном body раздел отсутствовал. Это [индексированный первичный фрагмент](https://developers.google.com/workspace/calendar/api/guides/recurringevents?authuser=19#modify_all_following_instances), а не проверка реализации MCP. Выбранный `update-event` публикует `thisAndFollowing`, но его живые результаты не проверены; две записи не объявляются транзакцией. [GC-API-13](../sources.md), [GCAL-NSPADY-TOOLS-2.7.0](../sources.md).

### Свободное время и busy/free

`freeBusy` возвращает интервалы busy с inclusive start/exclusive end; максимум expansion — 50 calendars/100 group members. Ошибки могут быть внутри результата отдельного календаря/группы, даже при успешном HTTP. **O:** календарь с ошибкой означает unknown, а не «свободен»; предлагать слот по объединению выбранных календарей с рабочими часами, длительностью и буферами пользователя. [FreeBusy](https://developers.google.com/workspace/calendar/api/v3/reference/freebusy/query), [GC-API-14](../sources.md).

REST `transparency=opaque` блокирует время, `transparent` — нет. **O:** обычный `default` event с `opaque` достаточен для блока под задачу; цвет и название не заменяют busy. Это копия намерения в календаре, а не завершение или перенос плановой даты задачи в SingularityApp. [Events](https://developers.google.com/workspace/calendar/api/v3/reference/events#resource), [GC-API-06](../sources.md), [CONTEXT](../../CONTEXT.md).

### Reminders, notifications и watch

Reminders приватны для пользователя: defaults в CalendarList, overrides в событии с `useDefault=false`; `email|popup`, максимум 5 overrides, 0–40320 минут до события. Calendar notifications — отдельные пользовательские email-настройки о создании/изменении/отмене/ответе/agenda. [Reminders](https://developers.google.com/workspace/calendar/api/concepts/reminders), [CalendarList](https://developers.google.com/workspace/calendar/api/v3/reference/calendarList), [GC-API-15](../sources.md), [GC-API-02](../sources.md).

**SRC** nspady 2.7.0 ([GCAL-NSPADY-SRC-2.7.0](../sources.md), чтение 2026-10-08, без runtime и Google): `create-event` и `update-event` принимают optional `reminders` — `{useDefault: boolean (обязателен внутри объекта), overrides?: [{method?: "email"|"popup" (default "popup"), minutes: number}]}`; create передаёт объект в `events.insert`, update — в тело `events.patch` (`all`, `thisEventOnly`); при `thisAndFollowing` старая часть получает patch только `recurrence`, а новая создаётся `events.insert` из копии исходного события, поверх которой переданные поля положены целиком. По документации Google patch заменяет массивы целиком, а вложенные объекты сливает с текущими, поэтому `overrides` передаётся полным набором ([patch](https://developers.google.com/workspace/calendar/api/guides/performance#patch), [GC-API-25](../sources.md)). `get-event`/`list-events` возвращают `reminders` события (`useDefault`, `overrides`), `reminders` входит в допустимые `fields`; `list-calendars` возвращает `defaultReminders` каждого календаря (`method`, `minutes`). Вызовов `calendarList.patch`/`update` в пакете нет: default reminders календаря через сервер не меняются. Схема сервера не проверяет пределы Google (5 overrides, 0–40320 минут) — их соблюдает скилл. Из слияния объектов следует, что patch `{useDefault:true}` у события с непустыми `overrides` может сохранить их рядом с `useDefault:true`. **PROJECT:** для «как в календаре» при изменении скилл передаёт `{useDefault:true, overrides:[]}` — пустой массив заменяет прежние `overrides`. **O:** без него patch может быть отклонён или сохранить прежние `overrides` — вывод из семантики patch без проверки; принятие Google формы с пустым массивом в runtime тоже не проверено.

**DOC:** в интерфейсе Google Calendar у календаря отдельно настраиваются «Event notifications» и «All-day event notifications» ([справка Google](https://support.google.com/calendar/answer/37242?hl=en), [GC-HELP-NOTIFICATIONS](../sources.md)). **O:** что `defaultReminders` в CalendarList и `list-calendars` относятся только к записям со временем, умолчания all-day через API не видны, а `minutes` у all-day отсчитываются от 00:00 дня — не проверено ни по справочнику API, ни в runtime. **PROJECT:** к all-day Событиям настройка «Напоминания Событий» не применяется; при `useDefault:true` у all-day действующий набор считается неизвестным. **PROJECT:** `jedikit-calendar` передаёт `reminders` по настройке типа записи или явной просьбе.

Push `watch` — канал HTTPS callback для хоста, а не reminder пользователю. Notification не несёт Event body: нужен read; channels истекают и сами не продлеваются, доставка не гарантирована. **O:** для стартового скилла не нужны webhook infrastructure или свой scheduler; фоновые обзоры могут читать по расписанию хоста по ADR 0003. [Push guide](https://developers.google.com/workspace/calendar/api/guides/push), [GC-API-16](../sources.md), [ADR 0003](../../docs/adr/0003-no-unattended-writes.md).

### eventType и цвета

`eventType` immutable после создания. API различает `default,birthday,focusTime,fromGmail,outOfOffice,workingLocation`; `fromGmail` создавать нельзя. Status events доступны на primary calendar и только eligible пользователям. FocusTime/OOO требуют timed start/end и `opaque`; workingLocation — properties, `public,transparent`, timed или однодневный all-day. Focus/OOO могут автоматически отклонять приглашения; focus также меняет Chat status. Личный Google Calendar не следует считать eligible для Workspace focusTime. [Event types](https://developers.google.com/workspace/calendar/api/guides/event-types), [status guide](https://developers.google.com/workspace/calendar/api/guides/calendar-status), [focus Help](https://support.google.com/calendar/answer/11190973), [GC-API-17](../sources.md), [GC-API-18](../sources.md), [GC-API-19](../sources.md).

**DOC.** У цвета три поверхности. Цвет календаря — пользовательское оформление `CalendarList` (`colorId` секции `calendar` либо RGB `backgroundColor`/`foregroundColor`, которые его supersede); у каждого пользователя свой. Цвет события — `Events.colorId`, индекс секции `event` палитры `GET /colors` из 11 значений; ответ содержит `background`/`foreground`, но не имена, имена Lavender…Tomato документирует Apps Script `EventColor`. ### Attendees/RSVP и происхождение события

Organizer управляет общими полями; RSVP меняет ответ собственной attendee copy и распространяется organizer. `accepted,tentative,declined,needsAction` различаются. Изменение shared content гостем может остаться в его copy и потеряться при organizer update. Настройки приглашений влияют на появление события; prefilled accepted не гарантирует его появления у гостя. **O:** не переносить чужую встречу вместо ответа на приглашение; Read-back должен проверить собственный responseStatus. [Inviting attendees](https://developers.google.com/workspace/calendar/api/concepts/inviting-attendees-to-events), [GC-API-21](../sources.md).

REST позволяет маркировать происхождение через `extendedProperties.private` (локально для calendarId+eventId) либо `shared` (доступно участникам). Ключ >44 символов отбрасывается, значение >1024 обрезается. `source.title/url` — отдельная creator-only ссылка происхождения. **PROJECT:** метки Брони и Распорядка хранятся в `description`; `extendedProperties` не являются обязательным форматом JediKit. Не хранить секреты/личные URL и не обещать двустороннюю синхронизацию. [Extended properties](https://developers.google.com/workspace/calendar/api/guides/extended-properties), [Events](https://developers.google.com/workspace/calendar/api/v3/reference/events), [GC-API-22](../sources.md), [GC-API-06](../sources.md).

У property search есть противоречие документации: guide говорит OR внутри private/shared и AND между группами, list reference — match all constraints. **O:** не строить дедупликацию на непроверенной Boolean семантике нескольких фильтров. PUT omission может удалить properties; PATCH позволяет удалить ключ через null. [Guide](https://developers.google.com/workspace/calendar/api/guides/extended-properties#search_properties), [list](https://developers.google.com/workspace/calendar/api/v3/reference/events/list), [GC-API-22](../sources.md), [GC-API-07](../sources.md).

### Delete, cancellation и уведомления участникам

`DELETE` удаляет event; `status=cancelled` в ресурсе означает cancelled/deleted, в том числе отменённое исключение series. Cancelled exception нельзя вновь показать при раскрытии parent; tombstones обычных удалённых событий могут исчезнуть. Не путать отмену organizer meeting, удаление своей копии и RSVP declined. Google Help описывает Trash с восстановлением в течение 30 дней; это не обещание доступного restore tool MCP или отмены уже отправленного письма. [Events resource](https://developers.google.com/workspace/calendar/api/v3/reference/events), [delete](https://developers.google.com/workspace/calendar/api/v3/reference/events/delete), [Help](https://support.google.com/calendar/answer/37113?hl=en), [GC-API-06](../sources.md), [GC-API-DELETE](../sources.md), [GC-DELETE-HELP](../sources.md).

REST `sendUpdates=all|externalOnly|none`; `sendNotifications` deprecated. Insert docs предупреждают: `none` может ломать синхронизацию во внешние календари и приводить к потере событий для некоторых пользователей; для migration есть import. **O:** уведомления — явная часть Preview и результата, «тихий режим» не универсальное решение. У официального Google MCP другой аргумент `notificationLevel`, default `ALL`; у выбранного nspady — `sendUpdates` (для update/delete schema default `all`). Эти контракты не смешиваются. [Insert](https://developers.google.com/workspace/calendar/api/v3/reference/events/insert#parameters), [delete](https://developers.google.com/workspace/calendar/api/v3/reference/events/delete), [MCP create](https://developers.google.com/workspace/calendar/api/v3/reference/mcp/tools_list/create_event), [GC-API-09](../sources.md), [GC-MCP-CREATE](../sources.md).

### Quotas, конкурентные изменения и recovery

На дату доступа docs публикуют 10 000 requests/min/project и 600/min/user/project; часть проектов с использованием до мая 2026 сохраняет прежние quotas. Есть operational/anti-abuse limits, `403/429`, backoff с jitter; конкретные quotas аккаунта не проверялись. Daily billing threshold — 1 млн/project; docs обещают детали будущей тарификации с предварительным уведомлением, это не подтверждение действующего платного тарифа. Для официального Google remote MCP опубликован отдельный quota cost: delete_event 10, остальные перечисленные tools 1; это не тариф операций nspady. [Usage limits](https://developers.google.com/workspace/calendar/api/guides/quota), [GC-QUOTA](../sources.md).

REST `If-Match: etag` защищает update/delete от конкурентного изменения (412); после конфликта нужно reread и новое решение. Для неопределённого результата create нельзя вслепую повторять запись. Custom event ID может помогать дедупликации, но Google не гарантирует обнаружение всех collision. **PROJECT:** хосту нужны ясные ошибки и recovery. У выбранного nspady create-event публикует custom `eventId`, но update/delete не публикуют `etag/If-Match`; отсутствие concurrency guard не устраняется собственным кодом JediKit. [Version resources](https://developers.google.com/workspace/calendar/api/guides/version-resources), [Events](https://developers.google.com/workspace/calendar/api/v3/reference/events), [GC-API-23](../sources.md), [GC-API-06](../sources.md), [ADR 0004](../../docs/adr/0004-no-custom-code.md).

Host sync/cache при необходимости обходит pages до `nextSyncToken`; incremental sync включает удаления, 410 требует full sync. Time-window filters несовместимы с syncToken. **O:** состояние синхронизации принадлежит хосту; для обычного «посмотри неделю» достаточно полного bounded list с pagination. [Sync guide](https://developers.google.com/workspace/calendar/api/guides/sync), [list](https://developers.google.com/workspace/calendar/api/v3/reference/events/list), [GC-API-24](../sources.md), [GC-API-07](../sources.md).

### Google Tasks — отдельный API

Google Tasks имеет отдельные resources `tasklists/tasks`, endpoint `tasks.googleapis.com` и scopes `tasks/tasks.readonly`; это не события Calendar API. Calendar UI показывает Tasks с датой и уже позволяет задавать время/длительность, но Tasks API `due` сохраняет только дату, отбрасывает время и прямо говорит, что это scheduled date, **не deadline**. Время задачи через API читать/писать нельзя. Видимость в Calendar UI не означает доступность через `events.list` или Calendar MCP. [Tasks REST](https://developers.google.com/workspace/tasks/reference/rest), [Task resource](https://developers.google.com/workspace/tasks/reference/rest/v1/tasks), [Calendar Help](https://support.google.com/calendar/answer/9901136?hl=en), [GC-TASKS-API](../sources.md), [GC-TASKS-RESOURCE](../sources.md), [CAL-TOOLS-09](../sources.md).

**PROJECT:** Бронь создаёт обычное событие Calendar и ссылается на задачу в SingularityApp. Перенос Брони не меняет задачу и наоборот; это не синхронизация с Google Tasks.

## Записи, Read-back и непроверенные слои

Принятые правила JediKit предназначены для `docs/adr/0014-confirmations.md` и `skills/jedikit-calendar/references/write-policy.md`: явная полная команда выполняется сразу с Read-back; явно названные несколько записей — последовательно, стоп на первой ошибке, отчёт applied/unverified/unapplied без автоматического отката. Предложение агента получает однострочное подтверждение; полный Preview нужен для набора, собранного агентом. Неоднозначные кандидаты или режим серии уточняются до записи. Фоновые запуски только читают по [ADR 0003](../../docs/adr/0003-no-unattended-writes.md).

Явное однозначное удаление события выполняется сразу. Google Help описывает 30 дней в корзине и восстановление через интерфейс; MCP restore tool не обещается. Это не откат уже отправленных уведомлений. После удаления нельзя считать timeout, `403` или отсутствие в неполном списке подтверждением успеха. Read-back должен адресовать прежние calendarId/eventId и различать подтверждённое удаление, отсутствие доступа и неизвестный исход. Если результат не подтверждён, `unverified`, без слепого повтора. [Delete Help](https://support.google.com/calendar/answer/37113?hl=en), [Events.delete](https://developers.google.com/workspace/calendar/api/v3/reference/events/delete), доступ 2026-10-07; [GC-DELETE-HELP](../sources.md), [GC-API-DELETE](../sources.md).

После create/update Read-back через `get-event` сверяет ID, calendar, изменённые поля, дату/пояс и метки; ответ write сам по себе его не заменяет. При неизвестном исходе create сначала читаются события, чтобы не создать дубль. Конфликт и дубль показываются пользователю отдельно; скилл не выбирает за него перенос соседних событий.

Живая проверка закрыла чтение нескольких календарей, создание, Read-back, instance IDs, три режима серии, удаление и ответы о конфликтах и дублях. **Не проверены**: работа через модель и регистрация 7 инструментов после `tools.include` (`hermes mcp test` видит 8, включая `manage-accounts`), OAuth refresh дольше одной сессии и отзыв доступа, полнота при многих календарях, пагинация реализации, DST, доставка уведомлений и recovery. Runtime не является отдельным обязательным ручным гейтом публикации; каждая реальная запись всё равно требует Read-back.

Риски: broad OAuth grant не ограничивается allowlist; неполный обзор и ошибка отдельного календаря не означают свободное окно; series edits и внешние уведомления не образуют обратимую транзакцию. Eligibility специальных Workspace event types не выводится из их присутствия в inputSchema. При нехватке инструмента скилл называет его базовое имя и рекомендует подключение средствами хоста, не меняя OAuth/credentials самостоятельно.
