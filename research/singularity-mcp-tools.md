## 35 vs 48: проверяемая разница

Предыдущий Codex app-server probe (`mcpServerStatus/list`, `detail: toolsAndAuthOnly`) при scopes `tasks:read/write/check`, `projects:read/write`, `tags:read/write`, `checklists:read/write`, `time_stat:read/write`, `mcp:read/write` сообщил тот же server `singularity-mcp ^2.0.1`, OAuth и **35 tools**. Поэтому нельзя утверждать, что каждая из 13 строк включается ровно одним конкретным scope без отдельного A/B probe по каждому scope.

## Что отсутствует по точному каталогу

- В 48 именах нет `delete`, `*_delete` или `batch` tool. Это подтверждает отсутствие **явного** permanent-delete/batch endpoint в данном `tools/list`; нельзя из этого вывести, что отдельное поле вроде `deleteDate` в schema не имеет серверной семантики.
- Архивирование присутствует только как `task_archive`/`task_unarchive` и `project_archive`/`project_unarchive`; это не permanent delete.
- Нет отдельного `task_bulk_*`, `project_bulk_*`, `checklist_bulk_*` или transaction tool. Цикл по объектам должен быть реализован клиентом и не считается batch capability сервера.
- Нет в этом каталоге `list_resources`, `read_resource`, `list_prompts`, `get_prompt`: Hermes может регистрировать utility wrappers поверх MCP primitives, но они не являются 48 объектами прямого `tools/list`; текущий probe эти primitives не вызывал.

## Server-side notes из initialize

Initialize сообщил `instructions`, среди которых: enum-поля (`priority`, `state`, `checked`, `reviewValidationInterval`) нужно передавать числовыми значениями; для lifecycle следует использовать специальные tools (`task_complete`, `task_cancel`, `task_uncomplete`, `task_archive`), а не `task_update`; `task_change_column` предназначен для kanban-перемещения; при неизвестном project/tag ID сначала использовать соответствующий `*_list`. Это инструкции сервера, не выполненные действия. Полный JSONL ниже сохраняет именно полученные schemas и annotations.
