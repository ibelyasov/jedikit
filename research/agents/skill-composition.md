# Границы скиллов и композиция JediKit

Срез и дата доступа к внешним источникам: **2026-10-07**. Локальный срез JediKit: commit `43fc19e8f2d175195b8a27e92646941e2252efbb`. Внешние основания и согласованный продуктовый контракт (§4) разделены: досье не подтверждает реализацию или runtime поведения скиллов. Источники — по ID в [едином реестре](../sources.md); доспрос — в [смежном досье](clarification.md).

## Краткие выводы и уровень оснований

- **Спецификация:** Agent Skills задаёт формат инструкций и ресурсов, но не переносимые зависимости skill→skill, порядок исполнения или call/return. Agent Plugins 1.0.0 задаёт упаковку и discovery, не оркестрацию. [SC-S-1](../sources.md), [PL-H-15](../sources.md); [Agent Skills](https://agentskills.io/specification), [Agent Plugins §§5–7](https://agent-plugins.org/specification).
- **Vendor docs / чтение source Hermes:** несколько скиллов могут находиться в одном контексте через preload или последовательные `skill_view`; выбор остаётся действием модели. Наличие инструкций не доказывает исполнение workflow или согласованность правил. См. §2.
- **Vendor guidance:** полезная граница — связная работа с ясным результатом. Ни «всегда один большой», ни «один скилл на каждое действие» не являются общей рекомендацией. [SC-S-2](../sources.md); [Design coherent units](https://agentskills.io/skill-creation/best-practices#design-coherent-units).
- **Чтение pinned source:** в Hermes reference нельзя прочитать через `../shared/...` из другого skill root. Это существенное ограничение для общей библиотеки правил. [SC-H-8](../sources.md); [Hermes](https://github.com/NousResearch/hermes-agent/blob/f97608f178d1ffeca59860195ab7da295f7c8e5f/tools/skills_tool_plugin.py).
- **Продуктовый контракт:** самостоятельные провайдерные скиллы, отдельный `jedikit-planning` для Плана дня и read-only навигатор `jedikit` по запросу; подробности в §4. Научного сравнения этой архитектуры JediKit нет.

Собственные модели и эксперименты не запускались. Ниже отдельно разобраны опубликованные эксперименты и обзоры, официальные рекомендации и авторские методы. Они не доказывают превосходство архитектуры JediKit: перенос результатов и продуктовая оценка явно отмечены как наша интерпретация.

## 2. Механика композиции в Hermes

### Загрузка инструкций: release source 0.21.5, без локального запуска

`skill_view` возвращает инструкции и metadata; сам workflow не исполняет. Prompt предлагает модели просмотреть индекс и загрузить подходящий skill. Несколько последовательных чтений могут дать несколько инструкций в контексте; это модельный выбор, не детерминированный dispatcher. [SC-H-3](../sources.md), [SC-H-7](../sources.md); [skill_view](https://github.com/NousResearch/hermes-agent/blob/f97608f178d1ffeca59860195ab7da295f7c8e5f/tools/skills_tool.py), [prompt](https://github.com/NousResearch/hermes-agent/blob/f97608f178d1ffeca59860195ab7da295f7c8e5f/agent/prompt_builder.py).

Explicit CLI preload принимает `hermes chat -s A,B` либо повторяемый `-s`; добавляет тексты в session `system_prompt`. Slash stacking объединяет до пяти leading skills в один user message, активный для turn. **Для portable plugin нельзя обещать slash UX:** его qualified names нужно получить из discovery; предыдущий платформенный аудит различает plugin registry и physical slash scanner. Безопаснее описывать preload и `skill_view` по фактическому имени. [PL-H-30](../sources.md), [SC-H-5](../sources.md), [PL-H-29](../sources.md), [SC-H-8](../sources.md); [parser](https://github.com/NousResearch/hermes-agent/blob/f97608f178d1ffeca59860195ab7da295f7c8e5f/hermes_cli/_parser.py), [preload](https://github.com/NousResearch/hermes-agent/blob/f97608f178d1ffeca59860195ab7da295f7c8e5f/cli.py), [stacking](https://github.com/NousResearch/hermes-agent/blob/f97608f178d1ffeca59860195ab7da295f7c8e5f/agent/skill_commands.py), [смежное досье](../platforms/hermes.md).

Plugin loader добавляет banner со sibling names и советом использовать qualified form. `related_skills` — metadata, не recursive dependency resolver. Native bundles — alias нескольких уже установленных skills, не установка недостающих. [SC-H-3](../sources.md), [SC-H-8](../sources.md), [PL-H-4](../sources.md); [sibling banner](https://github.com/NousResearch/hermes-agent/blob/f97608f178d1ffeca59860195ab7da295f7c8e5f/tools/skills_tool_plugin.py), [bundles docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills/#skill-bundles).

## 3. Рекомендации по размеру, границам и references

| Первичный источник, доступ 2026-10-07 | Заявленная рекомендация | Применимость |
| --- | --- | --- |
| Agent Skills specification / creator guidance | Metadata → инструкции → нужные ресурсы; рекомендуемые `SKILL.md <500` строк и <5000 tokens; ссылки в один уровень. Слишком узкая граница увеличивает загрузки и конфликты, слишком широкая ухудшает точность выбора. | Норматив формата и рекомендации размера различаются; числа не являются общим parser limit. [SC-S-1](../sources.md), [SC-S-2](../sources.md); [spec](https://agentskills.io/specification), [guidance](https://agentskills.io/skill-creation/best-practices) |
| Anthropic authoring guidance | Краткость; entrypoint <500 строк; тематические references, явное «когда читать»; избегать глубоких цепочек, TOC для длинных references. | Поддерживает домены внутри одного skill; не предписывает объединять все инструменты личной продуктивности. [SC-C-5](../sources.md); [progressive disclosure](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#progressive-disclosure-patterns) |
| OpenAI skills docs и pinned skill-creator | Ясные triggers, дешёвый discovery; self-contained skills; основные ограничения в entrypoint, условные подробности в references; простой skill не нуждается в router. | Общая guidance авторинга. В изученном creator нет отдельного обязательного числа 500 строк. [SC-O-7](../sources.md), [PL-O-1](../sources.md); [creator](https://github.com/openai/codex/blob/d27764b82f7118f674371e6d6e76271d9d606edb/codex-rs/skills/src/assets/samples/skill-creator/SKILL.md), [docs](https://developers.openai.com/codex/skills) |
| Nous Hermes skills docs | Индекс → skill → конкретный supporting file; compact entrypoint и тематические references; bundles для совместной загрузки. | Жёсткий общий предел строк не установлен; bundle не заменяет coordination workflow и не переносится как универсальная декларация. [PL-H-4](../sources.md); [docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills/) |

**Общие references имеют два разных смысла.** Внутри одного skill локальные тематические файлы естественно укладываются в progressive disclosure. Общий файл вне skill root в Hermes недоступен: `skill_view(...,file_path)` запрещает `..` и выход из выбранного skill. Зато можно выбрать **соседний skill по его qualified name**, затем прочитать `references/operation-policy.md` относительно него. Это чтение файла, не автоматическая загрузка его entrypoint. [SC-H-8](../sources.md); [reference serving](https://github.com/NousResearch/hermes-agent/blob/f97608f178d1ffeca59860195ab7da295f7c8e5f/tools/skills_tool_plugin.py).

**Наша интерпретация:** для JediKit хранить подробную policy у её провайдера и перед использованием читать owner `SKILL.md` плюс нужные references средствами хоста. Логическая ссылка «skill owner + relative reference» предпочтительнее предположения о `../shared`; это соглашение авторинга, а не новый manifest или resolver. До подтверждённого чтения нельзя заявлять, что соседний скилл вызван или его policy применена.

## 4. Применение в JediKit

Согласованный продуктовый контракт закрепляет одного ответственного за действие: задачи — `jedikit-tasks`, привычки и Ритуалы — `jedikit-habits`, События и Распорядок — `jedikit-calendar`. `jedikit-planning` отвечает за вместимость Плана дня и Брони, читая инструкции и правила владельцев операций. Ссылки от planning и навигатора к провайдерным скиллам односторонние; между провайдерами допустимы явные передачи работы. Ссылаться нужно по имени скилла, читать локальные references относительно выбранного владельца. Упоминание имени не доказывает фактическую загрузку.

Политика подтверждений согласована отдельно от внешних оснований: явные записи — сразу, предложение агента — одна строка и согласие, собранный агентом набор — один общий Preview. Запись последовательная, стоп на первой ошибке, отчёт applied/unapplied, без автоматического отката. После записи — Read-back; фоновые запуски только читают. Внешний `grill-me` уточняет намерение, но не заменяет правила владельца провайдера.

План дня отличается от Daily open: Фокус-лист проверяется по окнам календаря, предлагаются выборочные Брони. Бронь ссылается на задачу и не закрывает её. Навигатор вызывается по запросу и даёт карту возможностей; он не является обязательным маршрутизатором и не выполняет чужие сценарии. Эти положения — продуктовые решения, а не научно доказанное превосходство архитектуры.

Минимальные вопросы для будущего наблюдения пользователем: обычный capture; daily open без календаря; список событий; отметка привычки; общий вид дня; план с бронированием; отсутствие одного source; неоднозначное время; отказ host approval; неизвестный исход записи. Это перечень сценариев, **не новый модельный test runner и не обязательный runtime gate** по ADR 0004.

## 7. Границы проверки

Не проверены реальные false positives descriptions, конфликтная precedence, вложенное продолжение skill → skill и сохранение всех policies после compaction. Не выполнялись OAuth, provider writes/Read-back и модельные прогоны. Календарный контракт отдельно описан в [досье Google Calendar](../providers/google-calendar.md); его наличие не доказывает успешный runtime композиции.

## 8. Навигация и масштабирование

### 8.1. Три разных размера каталога

Ожидание владельца — **4–6 скиллов примерно по 10 пользовательских команд** — описывает продуктовый набор, а не 40–60 одновременно предъявленных модели function schemas. Нужно считать отдельно: (1) metadata доступных skills, по которым выбирается инструкция; (2) намерения/команды внутри выбранного SKILL.md; (3) инструменты подключённых провайдеров. Команда в Markdown сама по себе не регистрируется отдельным host tool или slash command. Discovery и загрузка этих уровней различаются. [SC-S-1](../sources.md), [SC-S-4](../sources.md); [Agent Skills integration](https://agentskills.io/client-implementation/adding-skills-support).

**Наша интерпретация:** опасение владельца прежде всего требует хорошей обнаруживаемости возможностей человеком и различимых результатов команд. Из найденных работ не следует численный потолок «6 skills», оптимальность структуры «6×10» или необходимость слияния. Размер **всего** установленного каталога хоста также может быть больше JediKit.

### 8.2. Навигатор, router, orchestrator и объединение

Термины ниже — функциональное различение для обсуждения, не стандартные типы Agent Skills. Один скилл может совмещать несколько ролей.

| Роль | Основной результат | Что происходит со специалистами | Цена / риск |
| --- | --- | --- | --- |
| Навигатор / help / входной skill | Ответить «что здесь можно сделать и какой поток подходит», показать примеры запросов и следующий шаг | Остаются самостоятельными; навигатор читает актуальные entrypoints перед советом | Ещё один вход и поддерживаемая карта; длинная карта сама затрудняет поиск |
| Router | Выбрать один или несколько skills по намерению и обеспечить их загрузку | Сохраняются; выбор может быть явным или неявным | Ошибка routing, лишний этап, invocation names из discovery; чтение не означает исполнение |
| Orchestrator / planning workflow | Получить сквозной результат: сопоставить источники, предложить слоты, провести подтверждённые операции | Policies и provider semantics остаются у owners | Конфликты инструкций, координация частичных результатов и записи; нужны правила остановки |
| Один объединённый skill | Выполнять все домены из одного entrypoint с локальными references | Самостоятельные skill boundaries исчезают | Один широкий trigger и внутренний routing; навигационная сложность переносится внутрь |

**Кейс `ask-matt`:** прочитан полный [SKILL.md](https://github.com/mattpocock/skills/blob/f3fc5632f401156837ee3872f14fe33ccf1024ea/skills/engineering/ask-matt/SKILL.md), commit **`f3fc5632f401156837ee3872f14fe33ccf1024ea`**, 2026-10-07. Автор прямо называет его router; entrypoint содержит `disable-model-invocation: true`. Он объясняет основной flow, ответвления и границы стадий, а перед утверждением о поведении специалиста требует читать его SKILL.md. В нашем функциональном различении это прежде всего **вызываемый человеком навигатор с рекомендацией маршрута**. Это не отдельная исполняемая машина состояний и не объединение всех специалистов; отсутствие runtime-проверки не позволяет обещать автоматическое продолжение. [SC-X-M3](../sources.md).

Для JediKit возможен вход «помоги выбрать сценарий»: кратко предложить задачи, привычки, события, общий вид, планирование, затем показать несколько подходящих примеров. Полный список 40–60 возможностей — по запросу или внутри выбранного раздела. «Показать день», `daily open` и «найти окна и забронировать» должны иметь разные ожидаемые результаты. Это **наша интерпретация**, не доказанная оптимальная длина меню. Навигатор не нуждается в provider calls и не получает права записи; planner из согласованного продуктового контракта решает другую задачу.

**Пробел:** прямой первичный experiment recognition-vs-recall или command-menu discoverability именно в текстовом LLM-агенте в этой ограниченной выборке не установлен. NN/g остаётся practitioner guidance, Furnas — исследованием несовпадения словаря, cognitive-load papers — учебными экспериментами. Они не заменяют друг друга.

## 9. Наука о композиции агентов: применимость к скиллам

Несколько SKILL.md у **одного** агента не образуют multi-agent system. Независимые агенты добавляют отдельные contexts, сообщения и coordination; planner skill может работать inline без них. Следующие работы полезны для оценки цены возможной оркестрации, но не доказывают необходимость router/master skill или вариант (b). Все три прочитаны выборочно по полным текстам; локальной репликации нет.

| Работа / дизайн и выборка | Результат | Сила, ограничения и перенос |
| --- | --- | --- |
| **Kim et al., Towards a Science of Scaling Agent Systems**, arXiv **2512.08296v3**, 2026-04-08, preprint. 260 configurations, пять топологий, три семейства моделей; Finance Agent 50 задач, BrowseComp Plus/WorkBench/Plancraft по 100, SWE-bench Verified/Terminal-Bench по 20. | Эффект относительно single-agent зависит от задачи: до **+80.8%** в financial reasoning и **−70.0%** в sequential planning (**относительные**, не п.п.). | Контролируемое сравнение с выравниванием максимальных суммарных iterations, не одинакового фактического compute. ## 11. Сопоставление оснований

Сопоставление не устанавливает измеренный optimum JediKit. Научные результаты, vendor guidance и кейсы сходятся по отдельным рискам, но исследуют разные поверхности.

## 12. Ограничения переноса оснований

Исследования retrieval и отдельных агентов не задают универсального числа скиллов или команд. Выбранные продуктовые границы перечислены в §4; они сохраняют самостоятельные провайдерные скиллы, отдельный План дня и read-only навигацию по запросу.

Не проверены качество help и русских descriptions для владельца, model selection в общем каталоге, retrieval success/latency/context usage, сохранение owner policies после compaction и eligibility native tool search. Число вопросов SC-N-A2 не установлено; Hick/Hyman и часть NN/g disclosure доступны лишь частично. Это ограниченная подборка, не systematic review. Досье не разрешает записи, расширение provider scope или смену подключений.
