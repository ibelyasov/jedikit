# JediKit Habits — trace решений grilling

Дата: **2026-08-29**. Этот файл восстанавливает исходные пары «вопрос → ответ пользователя → итоговое решение» из session log. Он предшествует реализации и не считается доказательством того, что текущий dirty tree соответствует решениям.

## Provider, reviews и release boundary

| Q   | Что решали                    | Ответ пользователя                                                                         | Итоговое решение                                                                                                                                                                                                                                                                                                                                    |
| --- | ----------------------------- | ------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Q27 | MCP degradation               | Да                                                                                         | Только официальный Habitify MCP и runtime `tools/list`; текущая операция fail closed при capability/schema gap; без REST/third-party fallback.                                                                                                                                                                                                      |
| Q28 | Adopt existing habit          | Да                                                                                         | Existing habit становится managed experiment только после явного adopt и согласованного плана; остальные можно читать, но не переписывать.                                                                                                                                                                                                          |
| Q29 | Weekly review                 | Да                                                                                         | Минимальный период, эксперименты по одному, решение `оставить / изменить / пауза`; timestamp только после полного review, без cursor; прерванный review начинается заново.                                                                                                                                                                          |
| Q30 | Pause/archive/delete и отпуск | Пользователь указал, что у Habitify есть vacation mode; пересмотренный вариант подтверждён | `pause <habit>` не притворяется нативным статусом: persistence только через реально обнаруженное поддержанное поле/напоминания, иначе это текущий conversational plan. `off` — нативный account-wide Off Mode; если MCP tool не найден, только UI-инструкция, без skip/archive эмуляции. Archive и delete не подменяют друг друга; delete отдельно. |
| Q31 | Partial failure               | Да                                                                                         | Sequential writes; stop on first error; read-back; `applied / error / unapplied`; без автоматического rollback.                                                                                                                                                                                                                                     |
| Q32 | Acceptance gate               | Да                                                                                         | Покрыть design/adopt/review/urge/pause, food/sexual, safety и dangerous advice, injection, confirmation matrix, partial failure/delete, schema drift/no fallback, privacy/reminders и evidence honesty.                                                                                                                                             |
| Q33 | Текущий scope delivery        | Да; затем пользователь отдельно потребовал убрать раздувшийся harness                      | Skill, академические references, package metadata, краткие docs и локальная валидация. Forward-review выполняется во временном workspace; сырые host/test artifacts и отдельный Python-harness в репозиторий не входят. Без tag, release, marketplace submission и реальных Habitify data/OAuth writes.                                             |
| Q34 | Routing между task/habit      | Да                                                                                         | `jedikit-habits` implicit; `jedikit-tasks` не использует Singularity habits scopes и не реализует habit workflow.                                                                                                                                                                                                                                   |

## Контроль полноты

- Q1–Q38 отражены по исходному session log, включая пересмотр Q12/Q30 и supersession Q35 финальным Q38.
- Исследовательские выводы не считаются пользовательскими решениями, если они не входят в подтверждённые ограничения выше.
- Текущий dirty implementation должен проверяться против этой трассировки; совпадение с уже написанным кодом не предполагается.
