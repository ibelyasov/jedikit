# В памяти агента только настройки

Native memory хранит timezone, рабочие дни, окна обзоров, режимы поддеревьев, ID выбранных привычек и ID областей Habitify, выбранных как Ритуалы, и `habitId` первой привычки каждого Ритуала: API не хранит порядок, а время старта Ритуала — напоминание первой привычки. Настройки календаря: домашний часовой пояс IANA, календарь записи (по умолчанию `primary`), календари чтения (по умолчанию все видимые), границы дня и зазор между Бронью и Событием или Распорядком. Это настройки пользователя, не копия состояния провайдеров.

Состояние задач, привычек, Ритуалов, календаря и обзоров не хранится: вчерашние хвосты daily open берёт из просроченных задач провайдера, дата следующего обзора эксперимента записана в его плане, пропущенный weekly не отслеживается — приглашает расписание. План дня и выполнение Ритуала каждый раз читаются из провайдеров. Хранение дат проведённых обзоров и восстановление по ним усложнили бы обзоры сильнее, чем дали пользы. Представление Ритуала областью и ограничения его интерпретации описаны в [досье ритуалов](../../research/habits/rituals.md).

## Consequences

Настройки сохраняются только встроенной памятью хоста, на Hermes — инструментом `memory`, одной компактной записью на скилл с префиксом `JediKit <скилл>:`. Файлы скиллов JediKit поставляет релиз, и хост подключает их только для чтения, поэтому настройки и состояние не записываются в `SKILL.md`, `references/` или файлы рядом, в том числе через `skill_manage` и файловые инструменты (файловая память самого хоста, как в Claude Code, — не каталог скиллов), даже если подсказка хоста советует хранить предпочтения в скилле ([досье Hermes](../../research/platforms/hermes.md)). Запись, ждущая подтверждения памяти хоста, не считается сохранённой.
