# Habitify через инструменты хоста по контракту OpenAPI v2

`jedikit-habits` получает операции Habitify от хоста. Официальный REST/OpenAPI v2 остаётся бизнес-контрактом; транспорт реализует доверенный OpenAPI→MCP-адаптер хоста или эквивалент с теми же именами операций. Ключ находится только у адаптера, агент получает только операции. Плагин не объявляет подключение и секреты ([ADR 0005](0005-one-source-host-connections.md)). Все 23 ожидаемые операции и их обязательные аргументы заданы в [`skills/jedikit-habits/tools.json`](../../skills/jedikit-habits/tools.json); применение и Read-back описаны в [справке инструментов](../../skills/jedikit-habits/references/habitify-tools.md).

Официальный Habitify MCP (`mcp.habitify.me`) отвергнут: в нём есть только отметки, статусы и список привычек за дату, без создания/изменения привычки, записи плана в заметку и архивации. REST/OpenAPI v2 покрывает эти операции. Основания: [досье провайдера](../../research/providers/habitify.md), [официальный OpenAPI v2](https://api-docs.habitify.me/openapi/v2/openapi-bundled.yaml). Это основание бизнес-контракта, не доказательство выполнения операций на хосте.

## Considered Options

- Только официальный Habitify MCP: скилл не может создать привычку и хранить план.
- Официальный Habitify MCP для отметок + REST для остального: две авторизации и два контракта без выигрыша в возможностях.
- `curl` с ключом в окружении агента: отвергнут, поскольку модель с terminal может прочитать ключ; инструкции не изолируют секрет от процесса агента.
- Привычки в SingularityApp: полный CRUD через MCP, но владелец пользуется Habitify.
