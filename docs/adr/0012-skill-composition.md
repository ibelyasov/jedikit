# У каждого действия один ответственный скилл

`jedikit-tasks` отвечает за задачи, проекты, Inbox и обзоры в SingularityApp; `jedikit-habits` — за эксперименты, отметки, области и Ритуалы в Habitify; `jedikit-calendar` — за вид календарей, События, Распорядок и настройки Google Calendar; `jedikit-planning` — за План дня, вместимость Фокус-листа и Брони; `jedikit` — за навигацию по запросу, карту команд и словарь. У каждого действия один явный ответственный. Перед записью в чужого провайдера скилл загружает скилл-владельца по имени через `skill_view` и читает его `references/write-policy.md` через `skill_view(..., file_path=…)`, затем применяет эти правила; чужие правила не пересказывает. Это сохраняет один источник политики для каждой операции ([досье композиции](../../research/agents/skill-composition.md)).

Ссылки идут от `jedikit-planning` и `jedikit` к провайдерным скиллам. Провайдерные скиллы не ссылаются на `jedikit-planning` и `jedikit` в инструкциях; `description` может назвать соседний скилл только для различения при выборе, например «План дня с задачами ведёт jedikit-planning». Связку Daily open → План дня показывает навигатор. Между провайдерными скиллами допускаются явные передачи: `jedikit-tasks` → `jedikit-calendar` для встречи из Inbox, `jedikit-habits` → `jedikit-calendar` для смены времени Ритуала с блоком Распорядка, любой скилл → `jedikit-tasks`, если запрос является задачей. Передача не считается состоявшейся без фактической загрузки скилла через `skill_view`. Формулировка «для операций SingularityApp/Habitify используй …» ограничивает операции конкретного провайдера и не запрещает композицию.

## Consequences

Полная явная команда на два провайдера выполняется в обоих последовательно без дополнительного подтверждения, с Read-back после каждой записи, остановкой на первой ошибке и отчётом applied/unverified/unapplied, без автоматического отката. Исключение для безвозвратных операций Habitify задаёт [ADR 0014](0014-confirmations.md). Набор изменений на двух провайдерах, собранный агентом, требует одного общего Preview и одного подтверждения, а затем того же порядка исполнения. При недоступности скилла-владельца или его инструментов агент называет невыполненную часть, не имитирует передачу и результат.
