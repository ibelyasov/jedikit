# Фоновые проверки только читают

Расписание JediKit — задания cron Hermes. Приглашения к обзорам `jedikit-tasks` и `jedikit-habits` создают инструментом `cronjob_manage(action="create", schedule, prompt, skills)` только по явной просьбе пользователя в чате или после его согласия на предложение агента по [ADR 0014](0014-confirmations.md) и сверяют через `cronjob_manage(action="list")` по ID задания. `deliver` не задаётся, кроме места, явно названного пользователем; по умолчанию доставка идёт в чат, где создано задание. Задание утренней сводки заводит Потребитель; `jedikit-calendar` и `jedikit-planning` его не создают. Prompt задания начинается маркером `[расписание jedikit]`; фоновый запуск только читает и приглашает к обзору. Найденные дубли тегов, пустые разделы, проекты без шага и прочая гигиена складываются в предложения для weekly и выполняются после одного подтверждения в чате. Владелец хотел часть обслуживания делать в фоне без вопросов, но нет данных, что агент надёжно угадывает смысл чужих категорий, а ошибочное фоновое объединение или удаление молча ломает систему пользователя.

## Consequences

В cron нет `clarify`, поэтому фоновый запуск не может получить согласие и не пишет. Поля timezone у задания нет: время считается по timezone профиля Hermes. Задание, запуск и доставка — разные результаты; уведомление приходит штатной доставкой cron. Фоновой утренней сводке нужны чтения задач и календаря в toolsets cron Hermes — это настройка cron Хоста, которую делает Потребитель (clanwright); скилл не расширяет toolsets задания сам.
