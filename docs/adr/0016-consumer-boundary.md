# JediKit задаёт поведение и ожидания, остальное делает репозиторий clanwright

JediKit — скиллы Hermes Agent: что и как Hermes делает в личной жизни и работе владельца по методологии каждой темы. Сейчас это личная продуктивность — задачи, привычки, календарь и План дня; рамка шире. Ожидания к инструментам JediKit объявляет в `skills/*/tools.json` и в разделе README «Что нужно от Hermes». MCP-серверы, адаптеры и другой код JediKit не реализует ([ADR 0004](0004-no-custom-code.md)).

Потребитель — репозиторий clanwright: он подключает JediKit к Hermes Agent владельца. Hermes Agent — Хост: загружает скиллы и их `references/` и вызывает инструменты. На стороне потребителя выбор, подключение и реализация инструментов и MCP по контракту, окружение и песочница Hermes, доступы, расписания и доставка, кроме приглашений, которые скилл создаёт по просьбе пользователя ([ADR 0003](0003-no-unattended-writes.md)), характер Hermes (`SOUL.md`) и его еженедельное самообучение, всё, что работает без модели, включение скиллов и развёртывание. Потребитель читает только README и `tools.json` закреплённой ревизии, поэтому README на верхнем уровне объясняет, что есть в JediKit, зачем и что нужно от Hermes.

Если сценарию нужен инструмент, которого у Hermes нет, JediKit добавляет ожидание в `tools.json` или в «Что нужно от Hermes»; реализует его потребитель. Задачи от потребителя приходят issue в репозиторий JediKit и передают рамку, а не спецификацию скилла: детали поведения владелец уточняет в JediKit.

## Considered Options

- Реализовывать недостающие инструменты в JediKit: противоречит [ADR 0004](0004-no-custom-code.md) и смешивает инструкции с кодом потребителя.
- Описывать в JediKit настройку подключений и развёртывания clanwright: дублирует источник истины потребителя и расходится с ним.
- Принимать от потребителя готовую спецификацию скилла: поведение решалось бы без словаря и ADR JediKit.

## Consequences

README и `tools.json` — внешний контракт с потребителем. Форму ответов инструментов, которые реализует потребитель (Адаптер хоста Habitify), README фиксирует как часть контракта; для готовых серверов её задаёт закреплённая в README версия. `references/` скилла применяют эту форму и не расширяют требования к потребителю. Имена инструментов меняются вместе со скиллом и отмечаются в release notes ([ADR 0005](0005-hermes-plugin-host-connections.md)). Агент JediKit не настраивает подключения, доступы, расписания и развёртывание и не правит репозиторий потребителя: он называет недостающее в контракте. Issues в репозитории — только входящие задачи потребителя; агент JediKit их не создаёт, а документы на них не ссылаются.
